# Word2vec

Word2vec своими руками: subsampling, negative sampling и как это ускоряет обучение.

- Subsampling частых слов — выкидываем «и», «в», «на» ещё до того, как они попали в пары.
- Negative sampling — вместо softmax по всему словарю учим модель отличать «настоящего соседа» от случайного слова.
- Sparse update — обновляем только те строки таблицы эмбеддингов, которые реально участвовали в батче.

## Что такое Word2vec

Word2vec — это не нейросеть для предсказания, а способ получить вектор для каждого слова так, чтобы близкие по смыслу слова оказались рядом в пространстве.

Идея «мешка контекста»: если два слова часто встречаются в похожих окружениях — они семантически близки. «Гарри» и «Волдеморт» не встречаются рядом, но оба встречаются рядом со словами «палочка», «заклинание», «магия» — значит, они в чём-то похожи.

Формально: для каждой пары (слово, сосед в окне) мы хотим, чтобы модель говорила «это настоящая пара» с высокой вероятностью, а для случайной пары — с низкой. Соседей берём из окна |d| <= W:

```text
гарри  поттер  жил  в  доме  номер  четыре  на  тисовой  улице
  └──────┴──────┴────┴──────┘
      окно W=4 вокруг «жил»
```

Модель — две таблицы E_in (вектор слова как центра) и E_out (вектор слова как соседа). 
Скор пары (скалярное произведение двух векторов: вектора контекста (ctx) и вектора target-слова (tgt)):
```text
score(ctx, tgt) = <E_in[ctx], E_out[tgt]> =  Σ_i E_in[ctx][i] · E_out[tgt][i]
p(ctx, tgt)     = σ(score)      // вероятность «настоящая пара»
```

Скалярное произведение двух векторов - одно число, насколько «согласованы» эти два вектора. 
Большое положительное — модель считает, что слова часто встречаются вместе; большое отрицательное — что не встречаются; около нуля — нейтрально.

**Проблема №1: корпус большой, а полезного сигнала мало**

Некоторые слова встречаются слишком часто. Другие - слишком редко. Без предобработки - хорошее обучение не построишь.

>Если «и» встречается 100 000 раз, оно даст 100 000 положительных пар (и ещё NEGATIVES × 100 000 отрицательных). 
> Модель будет переобучаться на «и»: выучит, что «и» — это просто «и», и что оно «похоже» на всё подряд, потому что встречается везде. 
> Полезного сигнала от «и» почти нет — она не несёт семантики. А времени на неё уходит — половина эпохи.

## subsampling - Взвешивание по частоте

Для каждого слова с относительной частотой f (доля в корпусе) выбрасываем его с вероятностью.

```text
P_drop(f) = max(0, 1 − sqrt(t / f))

где t — порог, обычно 1e-3 … 1e-5
Простыми словами: чем чаще слово, тем вероятнее оно будет выброшено. 
Редкие слова (f < t) не выбрасываются вообще. Частые (f >> t) выбрасываются почти всегда.
```

```java
// Subsampling: keepProb = (sqrt(f/t) + 1) * t / f, ограничено [0,1].
// Частые слова выпадают, редкие остаются. Стандарт word2vec.
for (int f : v.freq) {
    double rel = (double) f / totalCount;
    double keep = (Math.sqrt(rel / SUBSAMPLE_T) + 1.0) * SUBSAMPLE_T / rel;
    v.keepProb.add(Math.min(1.0, keep));
}
```

Формула keep = (sqrt(rel/t) + 1) * t / rel — это 1 − P_drop после алгебраических преобразований. Она даёт вероятность оставить слово. 
Применяется при построении пар.

Насколько ускоряет: если без subsampling на «и» уходило 50% пар, а с SUBSAMPLE_T = 1e-2 остаётся 1% — экономия почти 50% времени и улучшение качества: модель перестаёт тратить ёмкость на «и».

Где ещё это применимо
- Классификация с дисбалансом классов. Редкий класс — «полезный сигнал», частый — «фон». Балансировка (oversampling редкого или subsampling частого) — та же идея.
- Языковое моделирование (LM). GPT-стиль обучение на корпусе — та же проблема: «и», «в», «на» доминируют в loss, модель на них переобучается. Subsampling частых токенов (иногда с другим порогом, например t = 1e-4) ускоряет эпоху и улучшает перплексию на редких словах.

>Перплексия (perplexity, PPL) — это метрика качества языковой модели. Грубо: насколько модель «удивлена» правильным ответом. Чем меньше — тем лучше. Идеальная модель: PPL = 1.
> 
>Аналогия: «сколько вариантов модель держит в голове»
> 
>Представь, что модель на каждом шаге говорит: «правильный ответ — один из этих N токенов, я не уверена, какой именно». Перплексия — это эффективное N.
>- PPL = 2 — модель почти уверена, выбирает между двумя.
>- PPL = 100 — модель «размазана» по сотне вариантов.
>- PPL = 30 000 (размер словаря) — модель вообще ничего не выучила, все токены равновероятны.

Ключевая мысль: subsampling — это не потеря данных, а перераспределение внимания модели с частого (и бесполезного) на редкое (и информативное).

## negative sampling - как не считать softmax по всему словарю

Наивный подход к word2vec: для каждой пары (ctx, tgt) предсказывать tgt из всего словаря через softmax:
```text
p(tgt | ctx) = exp(<E_in[ctx], E_out[tgt]>) / Σ_{w ∈ vocab} exp(<E_in[ctx], E_out[w]>)
```

Softmax по 30 000 слов на каждую пару — это 30 000 умножений на вектор длины 64 только на forward. 
На 4.6M пар — 10¹² операций. 
Даже на современном железе — часы.

Negative sampling заменяет softmax на бинарную классификацию: «настоящая ли эта пара?». 
Для каждой positive пары (ctx, tgt) берём K случайных слов из словаря и учим модель говорить «0» для них:
```text
loss = −log σ(<E_in[ctx], E_out[tgt]>)                    // positive → 1
       − Σ_{k=1..K} log(1 − σ(<E_in[ctx], E_out[neg_k]>))  // negatives → 0
```

Теперь на каждую пару — K+1 скалярных произведений вместо vocab. При K = 3 и vocab = 30 000 это в 7500 раз меньше работы.

Как выбирать negatives

Равномерно по словарю — плохо: 99% негативов будут редкими словами, модель быстро выучит «любое редкое слово — negative», и на частых словах сигнала не будет.

Стандарт — по униграмме в степени 0.75: P_neg(w) ∝ freq(w)^0.75

Степень 0.75 «сглаживает» распределение: частые слова всё ещё сэмплируются чаще, но не настолько, чтобы доминировать. Эмпирически 0.75 — лучший выбор 

```java
private static int sampleNegative(Vocab vocab, Random rnd) {
    int n = vocab.size();
    double r = rnd.nextDouble() * vocab.negSamplingTotal;
    double acc = 0.0;
    for (int i = 0; i < n; i++) {
        acc += Math.pow(vocab.freq.get(i), NEG_SAMPLING_POWER);
        if (acc >= r) return i;
    }
    return n - 1;
}
```
Сложность — O(vocab) на сэмпл. При 4.6M пар × 3 негатива × 30 000 слов — 4·10¹¹ операций только на сэмплирование. Это узкое место, и в Word2VecNegativeSamplingDemoManual оно заменено на alias table.

Ключевая мысль: negative sampling — это замена дорогого softmax на дешёвую бинарную классификацию. Мы не теряем в качестве (модель всё равно учится различать «своё» и «чужое»), но экономим порядки.

## Alias table (Walker–Vose)

Идея: разбить единичный отрезок на n столбцов ширины 1/n. Для каждого столбца i хранить:
- prob[i] — вероятность «взять i» внутри столбца;
- alias[i] — альтернативный индекс с вероятностью 1 − prob[i].

Что это даёт на практике. В Word2VecNegativeSamplingDemo (линейный поиск) обучение шло ~13 секунд на эпоху. В Word2VecNegativeSamplingDemoManual (alias table + sparse update) — секунды, при том же качестве. Основной выигрыш — именно alias table, потому что negative sampling вызывается на каждую пару × K+1.

Где ещё это применимо
- Обучение с большим словарём. Любая задача, где «классов» десятки тысяч (LM, машинный перевод, NER на большом теге), — softmax дорогой. Negative sampling (или sampled softmax, или hierarchical softmax) — стандарт.
- Metric learning / contrastive learning. Siamese-сети, triplet loss, SimCLR — все они сэмплируют negatives. Alias table ускоряет сэмплирование в разы.
- Рекомендательные системы. Negative sampling по item'ам — стандарт (implicit ALS, BPR, YouTube DNN).

## EmbeddingLayer

EmbeddingLayer — это таблица поиска. Вход — индексы слов, выход — векторы.

```text
вход:  flat(T)          — T целых индексов
выход: seq(T, dModel)   — T векторов длины dModel
```

Аналогия: шкаф с ящиками

Представь шкаф с vocab ящиками. В каждом — dModel чисел (вектор слова). 
forward — это «достать ящик по номеру и положить его содержимое в выход». 
backward — «положить градиент обратно в тот же ящик, суммируя с тем, что уже лежит».

```text
         d0    d1    d2    d3
E[0]  [ 0.1  -0.3   0.7   0.2 ]   ← вектор слова «гарри»
E[1]  [-0.5   0.8   0.1  -0.9 ]   ← вектор слова «сказал»
E[2]  [ 0.4   0.4  -0.2   0.6 ]   ← вектор слова «хагрид»
...
E[2946] ...

forward([0, 2]) вернёт [E[0], E[2]] — вектор «гарри» и вектор «хагрид».
```

**Прямой проход**

```java
@Override
public float[] forward(float[] input, boolean training) {
    for (int t = 0; t < T; t++) {
        int idx = Math.round(input[t]);
        lastIdx[t] = idx;
        System.arraycopy(E[idx], 0, output, t * dModel, dModel);
    }
    return output;
}
```

Никакой арифметики — только копирование dModel float'ов из строки E[idx] в выход. Это очень быстро: dModel = 64 — 64 копирования на токен, ~50 наносекунд.


**Обратный проход**
```java
@Override
public float[] backward(float[] deltaNext) {
    for (int t = 0; t < T; t++) {
        int idx = lastIdx[t];
        int off = t * dModel;
        float[] eg = EG[idx];
        for (int j = 0; j < dModel; j++) eg[j] += deltaNext[off + j];
    }
    Arrays.fill(prevDelta, 0f);
    return prevDelta;
}
```

EG — это накопитель градиентов, та же форма [vocab][dModel]. 
Для каждого токена: прибавить deltaNext к строке EG[idx]. Никакой математики — только сложение.

EG[idx] накапливает сумму градиентов по всем вхождениям слова idx в батче. update(opt, batchSize) делит на batchSize и делает шаг оптимизатора. По сути, каждое слово «притягивается» к тем векторам, которые уменьшают loss, и «отталкивается» от тех, которые его увеличивают.

EmbeddingLayer.update (dense) вызывает optimizer.updateWeights(E, EG, batchSize) — идёт по всему E[vocab][dModel]. При vocab = 30 000, dModel = 64 это 1.92M элементов на каждый слой на каждый батч. Два слоя — 3.84M. При BATCH = 512 и ~1815 батчах на эпоху — ~7·10⁹ операций на эпоху, при том что реально в батче задействовано ~500 уникальных ctx и ~2000 tgt — это 8% строк.

Sparse update обновляет только задействованные строки.

Что это даёт. При touched ~ 2500 уникальных индексов из 30 000 — в 12 раз меньше работы. На эпоху — не 7·10⁹, а 6·10⁸. Плюс не нужно zeroGrad каждый батч (метод сам обнуляет EG[touched]), а это ещё O(vocab·dModel) экономии.

Ключевая мысль: если в батче участвует 8% словаря, обновлять 100% — это трата 92% времени. Sparse update — стандарт для больших таблиц.

## NegativeSamplingLayer

NegativeSamplingLayer — это очень маленький слой: два входа одинаковой длины, один выход.

```text
вход 0: ctx  — float[dModel]   (вектор контекста из E_in)
вход 1: tgt  — float[dModel]   (вектор target из E_out)
выход:  float[1]               — p = sigmoid(<ctx, tgt>)
```

Прямой проход

```java
@Override
public float[] forwardN(float[][] inputs, boolean training) {
    float[] ctx = inputs[0], tgt = inputs[1];
    float s = 0f;
    for (int i = 0; i < dModel; i++) s += ctx[i] * tgt[i];
    output[0] = sigmoid(s);   // σ(<ctx, tgt>)
    return output;
}
```

Скалярное произведение двух векторов + сигмоида. Всё. Никаких весов — сам слой параметров не имеет, они в EmbeddingLayer.

Обратный проход

```java
@Override
public float[][] backwardN(float[] deltaNext) {
    float p = output[0];
    float dScore = deltaNext[0] * p * (1f - p);   // dL/ds = dL/dp · σ'(s)

    float[] dCtx = new float[dModel];
    float[] dTgt = new float[dModel];
    for (int i = 0; i < dModel; i++) {
        dCtx[i] = dScore * tgtRef[i];   // dL/dctx = dL/ds · tgt
        dTgt[i] = dScore * ctxRef[i];   // dL/dtgt = dL/ds · ctx
    }
    return new float[][]{ dCtx, dTgt };
}
```

Ключевая мысль: NegativeSamplingLayer — это простейший способ учить парные сходства. Он не хранит параметров, вся семантика — в эмбеддингах, а слой лишь превращает «близость» в вероятность.

## Как это учится

Представь positive-пару (ctx=«гарри», tgt=«поттер», label=1). Модель хочет σ(<E_in[гарри], E_out[поттер]>) близко к 1, то есть скалярное произведение — большое положительное. Градиент толкает E_in[гарри] и E_out[поттер] навстречу друг другу (в одном направлении).

Теперь negative-пара (ctx=«гарри», tgt=«дом», label=0). Модель хочет σ(...) близко к 0, скалярное произведение — большое отрицательное. Градиент толкает E_in[гарри] и E_out[дом] в разные стороны.

После многих эпох: «гарри» и «поттер» — рядом, «гарри» и «дом» — далеко. Именно это мы и видим в логах Word2VecNegativeSamplingDemoManual после 5 эпох:

```text
ближайшие к 'гарри':
   1. виду        cos=0.7108
   2. только      cos=0.5938
   3. успел       cos=0.5751
   4. замка       cos=0.5723
   5. руками      cos=0.5708
```

«Виду», «замка», «руками» — это не синонимы «гарри», но в книге они часто появляются в похожих контекстах («Гарри увидел замок», «Гарри взял в руки»). Эмбеддинги выучили контекстную близость, а не синонимию. Это и есть word2vec.

А вот «профессор» из Word2VecNegativeSamplingDemo (первый прогон, dense):
```text
ближайшие к 'профессор':
   1. макгонагалл  cos=0.7515
   2. флитвик      cos=0.6188
   3. твердо       cos=0.5673
   4. спраут       cos=0.5555
   5. снэйп        cos=0.5171
```

Макгонагалл, Флитвик, Спраут, Снэйп — это всё профессора Хогвартса. Модель выучила категорию «профессор» → «профессора». Идеальный пример того, что эмбеддинги ловят семантические классы.

[Word2VecNegativeSamplingDemo](../ext/word2vec/Word2VecNegativeSamplingDemo.java) — «как это выглядит в графе»

Здесь используется Functional — декларативный граф из слоёв.
- Читается как схема: два входа → две EmbeddingLayer → NegativeSamplingLayer → выход;
- ModelTraining делает всю рутину: перемешивание, батчи, clip, метрики, early stopping;
- серализация бесплатно: model.save(path) — и вся сеть с весами на диске.

Минусы:
- накладные на каждый пример: Functional обходит топологию, клонирует дельты, аллоцирует deltaAccum. Для word2vec, где пример — это пара индексов, накладные доминируют над полезной работой;
- dense update/zeroGrad: ModelTraining не знает про sparse, поэтому обновляет весь словарь каждый батч;
- медленно: ~13 секунд на эпоху на 2947 словах.

[Word2VecNegativeSamplingDemoManual](../ext/word2vec/Word2VecNegativeSamplingDemoManual.java)— «как это ускорить»

Здесь ручной цикл. Плюсы:

1 forward ctx на группу вместо K+1: ctx считается один раз, dL/dctx суммируется;
- sparse AdamW: обновляются только задействованные строки;
- alias table: O(1) на negative sample;
- никаких NInputSample в горячем пути: int[] на батч;

быстро: секунды на эпоху при том же качестве.

Минусы:
- сложнее для чтения: ручной батчинг, touched-флаги, спарс-AdamW;
- нет ModelTraining: перемешивание, clip, early stopping — вручную (здесь их нет — для учебного примера достаточно);
- сериализация вручную: EmbeddingLayer.save/load для двух файлов (или через Functional, если завернуть в граф).

Итого: subsampling, negative sampling, alias table и sparse update — это не «магические константы word2vec», а четыре универсальных приёма ускорения и стабилизации обучения с большим словарём.
