# Strided view

Тензор это многомерный массив.

В памяти тензор хранится как плоский массив (float[] data).

Следовательно, ему нужны дополнительные свойства позволяющие интерпретировать плоский массив как многомерный и вот они:
- offset — с какого элемента этого буфера начинается тензор.
- shape — размеры по осям (измерениям).
- strides — сколько элементов нужно пропустить в памяти, чтобы сдвинуться на 1 по каждой оси (измерению).

Адрес элемента с индексами (i, j, k) считается так: offset + i * stride0 + j * stride1 + k * stride2

```text
flat = offset + i0 * strides[0] + i1 * strides[1] + ... + iN * strides[N]
```
Такая тройка `(offset, shape, strides)` над общим буфером называется strided view (или просто «вью»). 
Ключевое свойство: несколько тензоров могут смотреть в один и тот же буфер, но видеть в нём разные «логические» массивы. 
Именно на этом держатся все дешёвые операции (transpose, slice, broadcast) — они меняют только метаданные, но не данные.

Примеры тензоров

| Ранг | Что это | Пример формы | Пример |
| --- | --- | --- | --- |
| 0 | скаляр | `()` | `loss = 0.5` |
| 1 | вектор | `(3,)` | `[1, 2, 3]` |
| 2 | матрица | `(2, 3)` | таблица 2×3 |
| 3 | куб чисел | `(B, T, C)` | батч последовательностей |
| 4 | пачка картинок | `(B, C, H, W)` | 32 картинки RGB 224×224 |

В ML почти всегда первая ось — batch (размер пачки).
Пример: (32, 3, 224, 224) — 32 картинки, 3 канала, высота 224, ширина 224.

Про ранги стоит оговориться: ранг 0 (скаляр) и ранг 4 (батч картинок) — это разные миры по частоте использования. 
На практике 90% времени вы работаете с рангами 2–4, а ранг 0 нужен ровно для loss. 
Это полезно помнить, когда думаете, какие операции оптимизировать в первую очередь.

Пример: матрица 2×3, хранящаяся по строкам (row-major):
```text
offset:  0
Shape:   (2, 3)
Strides: (3, 1)
Буфер:   [1, 2, 3, 4, 5, 6]

Элемент (i, j) находится в буфере по индексу: i * 3 + j * 1

(0,0) -> 0*3+0 = 0 -> 1
(0,1) -> 0*3+1 = 1 -> 2
(0,2) -> 0*3+2 = 2 -> 3
(1,0) -> 1*3+0 = 3 -> 4
(1,1) -> 1*3+1 = 4 -> 5
(1,2) -> 1*3+2 = 5 -> 6

Матрица:
[[1, 2, 3],
 [4, 5, 6]]
```

## Contiguous

**Contiguous (непрерывный).** Тензор называется contiguous, если его элементы лежат в буфере в том же порядке, в каком их обходит логический row-major (C-style) обход индексов.

Формально: strides == contiguousStrides(shape) и offset == 0.

Интуиция: если «пройтись» по тензору в порядке (0,0,0) → (0,0,1) → ... → (max,max,max), физические индексы в data[] будут идти подряд: 0, 1, 2, 3, …

```text
contiguous:       shape=(2,3), strides=(3,1), offset=0
                  data = [1,2,3,4,5,6]
                  элемент (i,j) лежит в data[i*3 + j]

non-contiguous:   транспонированная (3,2), strides=(1,3), offset=0
                  data тот же [1,2,3,4,5,6]
                  элемент (i,j) лежит в data[i*1 + j*3]

Во втором случае логический обход (0,0),(0,1),(1,0),(1,1),... 
даёт физические индексы 0,3,1,4,2,5 — это не подряд. Значит, тензор не contiguous.
```

Зачем это нужно.
- reshape как view работает только для contiguous. Если элементы лежат в буфере подряд, то переинтерпретировать (2,6) → (3,4) можно, просто заменив shape и strides — данные не меняются местами. Если бы тензор был non-contiguous, такой трюк сломал бы соответствие «логический элемент ↔ ячейка буфера».
- Cache locality. Обход contiguous-памяти линеен — процессор это любит. Обход non-contiguous (например, по столбцам транспонированной матрицы) — это прыжки по памяти, кэш промахивается.
- Простота работы с градиентом. Градиент удобно хранить contiguous: тогда его можно рассматривать как плоский массив длины numel, и backward-функции пишут в него напрямую по индексу. Если бы градиент был «view с strides», каждый backward-метод был бы вынужден возиться со шагами.
- BLAS и низкоуровневые рутины (matmul, свёртки) ожидают contiguous-входы. Если у тебя non-contiguous view, приходится материализовать его копию — это .contiguous() за O(N).

В нашем коде градиенты всегда contiguous в логической форме. 
Для view-тензоров это отдельный буфер длины numel(shape), а transpose.backward / reshape.backward перекладывают его обратно в layout оригинала.

Практическое следствие, о котором часто забывают: contiguous — это не «свойство тензора вообще», а свойство пары (shape, strides, offset). 
Один и тот же буфер может быть представлен и contiguous-, и non-contiguous-вью. 
Именно поэтому is_contiguous — это метод, а не поле тензора.

## numel

numel = "num(ber of) el(ements)" — количество логических элементов тензора.

numel(shape) = shape[0] * shape[1] * ... * shape[n-1]

Например, для shape (2, 3, 4) → numel = 24. Это не то же самое, что data.length (размер буфера): у view-тензора буфер может быть больше, а numel считается только по его собственному shape.

Именно на этом различии (numel vs data.length) ломается наивная реализация sum() или zeroGrad(): они должны пройти numel логических позиций, а не data.length физических. Для contiguous-тензора это одно и то же, для вью — нет.

## Broadcasting

Broadcasting (растягивание) — это механизм, который позволяет выполнять поэлементные операции над массивами разной формы. 
Идея проста: «маленький» массив неявно растягивается (дублируется) до размеров «большого», чтобы можно было сделать операцию поэлементно. 
При этом физически память не копируется — используется хитрое вычисление индексов через strides.

Как выравниваются размеры (правила broadcasting)

Для двух массивов сравнивают их размерности справа налево (по последним осям). 
Правило такое: для каждой пары размерностей они должны быть либо:
- равны, либо
- одна из них равна 1, либо
- одна из размерностей отсутствует (тогда она считается как 1).

Скаляр + тензор(матрица)
```text
Offset:  0
Shape:   (2, 2)
Strides: (2, 1)
Буфер:   [1, 2, 3, 4]     то ест это матрица [[1., 2.], [3., 4.]]

+

Offset:  0
Shape:   ()
Strides: ()  
Буфер:   [10]

=

Offset:  0
Shape:   (2,  = max(2, 1) = 2    Последняя ось: у A это 2, у B оси нет → считаем её как 1
         2)   = max(2, 1) = 2    Предпоследняя ось: у A это 2, у B тоже нет → считаем как 1
Strides: (2, 1)
Буфер:   [11, 12, 13, 14]     то есть это матрица [[11, 12], [13, 14]]

То есть скаляр 10 трактуется как массив [[10, 10], [10, 10]], но без реального копирования в памяти.

Как это работает через strides
У A strides (2, 1): чтобы перейти к следующей строке, нужно сдвинуться на 2 элемента, к следующему столбцу — на 1.
У скаляра B strides (): он не имеет осей, и при broadcasting каждая его «виртуальная» ось получает stride 0. То есть при движении по любой оси индекс в буфере B не меняется — мы всё время читаем один и тот же элемент 10.

Поэтому при вычислении A[i, j] + B индекс в буфере B всегда 0 (плюс offset 0), и мы берём buffer_B[0] = 10
```

вектор + матрица
```text
Offset:  0
Shape:   (2, 3)
Strides: (3, 1)
Буфер:   [1, 2, 3, 4, 5, 6]       то есть это матрица [[1., 2., 3.],
                                                       [4., 5., 6.]]
+
Offset:  0
Shape:   (3,)
Strides: (1,)                
Буфер:   [10, 20, 30]        то есть это вектор [10, 20, 30] 

=

Offset:  0
Shape:   (2,   = сь 0: у A это 2, у B оси нет (вектор одномерный) → считаем отсутствующую размерность как 1. Пара (2, 1)    max(2, 1) = 2
          3)   = Ось 1 (последняя): у A это 3, у B это 3 → совпадают, всё ок.                                               max(3, 3) = 3
Strides: (3, 1)
Буфер:   [11, 22, 33, 14, 25, 36]

Вектор B = [10, 20, 30] трактуется как матрица размера (2, 3), где каждая строка — копия этого вектора:
При этом физически копировать его не нужно: благодаря strides, при движении по оси 0 (по строкам) индекс в буфере B не меняется (stride по отсутствующей оси считается 0), а по оси 1 — меняется как обычно (stride 1).
```

broadcasting — это чистая работа с метаданными. Никаких новых данных в буфере не появляется. Меняются только shape и strides, причём у растянутых осей stride становится 0.

Это ключевое место всей главы: stride = 0 — это и есть «бесплатное» копирование. Один и тот же элемент буфера читается снова и снова, но никакой памяти под копии не выделяется.

```java
    // Вычислить итоговую форму для результирующего тензора при операции над двумя тензорами зная их формы
    private static int[] computeBroadcastShape(int[] shape1, int[] shape2) {
        int maxRank = Math.max(shape1.length, shape2.length);
        int[] resultShape = new int[maxRank];

        for (int i = 0; i < maxRank; i++) {
            int idx1 = shape1.length - 1 - i;
            int idx2 = shape2.length - 1 - i;

            int d1 = (idx1 >= 0) ? shape1[idx1] : 1;
            int d2 = (idx2 >= 0) ? shape2[idx2] : 1;

            if (d1 == 1 || d2 == 1 || d1 == d2) {
                resultShape[maxRank - 1 - i] = Math.max(d1, d2);
            } else {
                throw new IllegalArgumentException(
                    "Incompatible shapes for broadcasting: " +
                    java.util.Arrays.toString(shape1) + " and " + java.util.Arrays.toString(shape2)
                );
            }
        }
        return resultShape;
    }
```

## Пример транспонирования матрицы

Транспонирование матрицы(когда строки становятся столбцами, а столбцы — строками)  — это операция, которая меняет местами строки и столбцы.
В наивной реализации ты бы создал новый буфер и перекопировал элементы:
```java
// Наивно (плохо)
double[][] transpose(double[][] m) {
    double[][] result = new double[m[0].length][m.length];
    for (int i = 0; i < m.length; i++)
        for (int j = 0; j < m[0].length; j++)
            result[j][i] = m[i][j];
    return result;
}
```

В strided-представлении транспонирование — это просто обмен strides местами:
```text
Было:  Shape: (2, 3), Strides: (3, 1)
Стало: Shape: (3, 2), Strides: (1, 3)

Буфер остаётся тем же! [1, 2, 3, 4, 5, 6]

Проверим:
Элемент (i, j) находится по индексу: i * 1 + j * 3
(0,0) -> 0+0 = 0 -> 1
(0,1) -> 0+3 = 3 -> 4
(1,0) -> 1+0 = 1 -> 2
(1,1) -> 1+3 = 4 -> 5
(2,0) -> 2+0 = 2 -> 3
(2,1) -> 2+3 = 5 -> 6

Получили:
[[1, 4],
 [2, 5],
 [3, 6]]
Это транспонированная матрица. O(1) по времени и памяти.
```

Применяются к каждому элементу независимо через вычисление плоских индексов и последующего обращения к буферу каждого из тензоров.

Сворачивают тензор по одному или нескольким измерениям.

| Операция | Что делает | Зачем |
| --- | --- | --- |

Отдельно стоит сказать про argmax и max: они часто нужны в паре. max теряет информацию о том, где был максимум, а argmax — о самом значении.

## Пример

### Самый минимальный тензор

Тензор — это плоский массив + форма. Никаких вложенных массивов, никаких float[][]. Это принципиально:

- память выделяется одним куском (new float[2*3*4]), а не 2×3 массивами;
- элементы лежат подряд (row-major), что даёт кэш-дружественный обход;
- размерность может быть любой — форма хранится массивом.

final — потому что после создания тензора и буфер, и форма не меняются. Тензор неизменяем по структуре (immutable по ссылкам), хотя сами значения в data — да, меняются через set.

Минимальный тензор отвечает ровно на один вопрос: «как по многомерному индексу найти элемент в плоском массиве?» — и делает это

```java
/**Самый минималистичный вариант тензора*/
public class Tensor {
    final float[] data; // плоский буфер всех элементов
    final int[] shape;  // размер по каждой оси, например [2, 3, 4]

    public Tensor(int... shape) {
        this.shape = shape.clone();
        this.data = new float[prod(shape)];
    }

    /**Общее кол-во элементов. Размерность тензора*/
    static int size(int[] s) {
        int n = 1;
        for (int x : s) n *= x;
        return n;
    }

    /**Чтение по многомерному индексу.
     * Индекс (i[0], i[1], ..., i[n-1]) превращается в плоский f по формуле row-major (C-порядок):
     * f = ((i[0] * shape[1] + i[1]) * shape[2] + i[2]) * ... + i[n-1]
     * Это тот же самый результат, что и Σ i[k] * stride[k], где stride[k] = prod(shape[k+1..]). Но мы не храним strides — вычисляем flat "на лету" для простоты и проигрывая в скорости
     * для strides-версии достаточно было f += idx * strides[k]
     * */
    public float get(int... i) {
        int f = 0;
        for (int k = 0; k < i.length; k++) f = f * shape[k] + i[k];
        return data[f];
    }

    /**Аналогичным образом - запись по многомерному индексу*/
    public void set(float v, int... i) {
        int f = 0;
        for (int k = 0; k < i.length; k++) f = f * shape[k] + i[k];
        data[f] = v;
    }
}
```

Код в get — это схема Горнера для вычисления линейного индекса. 
Обратите внимание на неочевидное свойство: цикл идёт слева направо, f на каждом шаге домножается на shape[k], а не на «правильный» stride. 
Это работает только потому, что для row-major канонический stride — это произведение всех правых размеров, и схема Горнера «сворачивает» это произведение на лету. 
Как только вы добавляете offset и произвольные strides (см. следующий раздел), схема Горнера перестаёт работать — приходится хранить strides явно.


в get вычисляем плоский индекс через "алгоритм линейного индекса"
```text
shape = [2,3]
data = {1, 2, 3, 4, 5, 6}

тензор = [[ 1,  2,  3],
          [ 4,  5,  6]]
          
Элемент [0, 1] 
    flat = 0
    flat = 0 * 2 + 0 = 0
    flat = 0 * 3 + 1 = 1    data[1] == 2
Элемент [1, 2]
    flat = 0
    flat = 0 * 2 + 1 = 1
    flat = 1 * 3 + 2 = 5    data[5] == 6         
```

Для тензора формы [d0, d1, d2, ..., d_{k-1}] и индексов [i0, i1, i2, ..., i_{k-1}]

линейный индекс в плоском массиве:
$$
\text{pos} = i_0 \cdot (d_1 d_2 \cdots d_{k-1}) + i_1 \cdot (d_2 d_3 \cdots d_{k-1}) + \cdots + i_{k-2} \cdot d_{k-1} + i_{k-1}
$$

```text
Вывод формулы:

Представь двумерный массив (матрицу) формы [d0, d1]. Чтобы добраться до элемента с индексами [i0, i1], нужно:

Сначала пройти i0 строк. В каждой строке d1 элементов, поэтому на переход через i0 строк уйдёт i0 * d1 позиций.
Затем внутри нужной строки сдвинуться на i1 позиций вправо.
Итого линейный индекс: pos = i0 * d1 + i

Теперь расширим идею на три измерения. Пусть форма [d0, d1, d2]. Элемент [i0, i1, i2]:

Сначала идём по оси 0: i0 * (d1 * d2) — потому что «блок» по осям 1 и 2 содержит d1 * d2 элементов.
Потом по оси 1: i1 * d2 — внутри блока по оси 0 мы переходим на i1 подблоков, каждый размером d2.
И наконец, по оси 2: + i2.
Получаем: pos = i0 * (d1 * d2) + i1 * d2 + i2.

Индукцией по числу осей это обобщается на любое k: каждый коэффициент при i_j — это произведение всех размеров справа от оси j. 
Именно эти коэффициенты и называются strides.
```


### Чуть более сложный тензор

Следующий шаг — добавить strides и offset. 
Это то, что превращает «просто n-мерный массив» в тензор с вью.

И изменилась формула доступа:

Было: f = i0 * shape[1] + i1 * shape[2] + ... — вычисляем «на лету» через схему Горнера, strides не хранятся.

Стало: f = offset + i0 * strides[0] + i1 * strides[1] + ... — strides хранятся, формула тривиальна.

Почему это важно: strides можно менять, не трогая буфер. Именно поэтому transpose, slice, broadcastTo работают за O(1).

Формула вычислени линейного индекса
$$
\text{pos} = i_0 \cdot (d_1 d_2 \cdots d_{k-1}) + i_1 \cdot (d_2 d_3 \cdots d_{k-1}) + \cdots + i_{k-2} \cdot d_{k-1} + i_{k-1}
$$
превращается в

Именно эти множители и есть strides

strides[i] — это произведение всех размерностей справа от оси i (то есть по осям i+1, i+2, …)

Для shape = [d0, d1] = [2, 3]:
- strides[0] = d1 = 3 — справа от оси 0 стоит только ось 1 размера 3.
- strides[1] = (произведение пусто) = 1 — справа от оси 1 ничего нет, поэтому по определению это 1.

```java
//вычисление strides по shape
//strides[i] = d{i+1} * d{i+2} * .... d{k-1}.  Если i == k -1 то strides[i] == strides[k-1] = 1
int stride = 1;
for (int i = shape.length - 1; i >= 0; i--) {
    strides[i] = stride;
    stride *= shape[i];
}
```

и с strides формула позиции превращается
$$
\text{pos} = i_0 \cdot \text{strides}[0] + i_1 \cdot \text{strides}[1] + \cdots + i_{k-1} \cdot \text{strides}[k-1]
$$

```java
public class Tensor {
    final float[] data;  // плоский буфер всех элементов
    final int offset;    // с какого места буфера начинается логический элемент [0,0,...,0]
    final int[] shape;  // размер по каждой оси  
    final int[] strides;// сколько элементов буфера пропустить при +1 по каждой оси

    // всегда создаёт новый буфер и contiguous-тензор
    public Tensor(int... shape) {
        this.data = new float[prod(shape)];
        this.offset = 0;
        this.shape = shape.clone();
        this.strides = canonical(shape);
    }

    //Все views (transpose, slice, broadcastTo) идут через приватный конструктор и не аллоцируют данные.
    private Tensor(float[] data, int offset, int[] shape, int[] strides) {
        this.data = data;
        this.offset = offset;
        this.shape = shape;
        this.strides = strides;
    }

    //вернёт размер тензора по его форме
    static int size(int[] s) {
        int n = 1;
        for (int x : s) n *= x;
        return n;
    }

    //вычисляем strides через shape
    static int[] canonical(int[] shape) {
        int[] strides = new int[shape.length];
        int stride = 1;
        for (int i = shape.length - 1; i >= 0; i--) {
            strides[i] = stride;
            stride *= shape[i];
        }
        return strides;
    }

    //Получить элемент
    //flat = offset + Σ idx[i] * strides[i].
    public float get(int... i) {
        int f = offset;
        for (int k = 0; k < i.length; k++) f += i[k] * strides[k];
        return data[f];
    }

    public void set(float v, int... i) {
        int f = offset;
        for (int k = 0; k < i.length; k++) f += i[k] * strides[k];
        data[f] = v;
    }

    //Показывает "силу" strides. Нам не надо копировать тензор. Просто меняем его форму и шаги
    public Tensor transpose() {
        return new Tensor(data, offset, new int[]{shape[1], shape[0]}, new int[]{strides[1], strides[0]});
    }

    //Срез по одной из осей. Также никакого копирования массива.
    //срез матрицы - вектор. Срез вектора - скаляр и так далее.
    public Tensor slice(int axis, int start, int end) {
        int[] s = shape.clone();
        s[axis] = end - start;
        return new Tensor(data, offset + start * strides[axis], s, strides);
    }

    /**
     * Broadcast-вью к заданной форме — O(1).
     * Выравниваем формы по правому краю; ось размера 1 (или новая
     * Идея: ось, которую «растягиваем», получает stride = 0. Тогда при движении по этой оси flat-индекс не меняется, и читается один и тот же элемент буфера.
     */
    public Tensor broadcastTo(int... newShape) {
        int[] st = new int[newShape.length];
        int shift = newShape.length - shape.length;
        for (int i = 0; i < newShape.length; i++)
            st[i] = i < shift ? 0 : (shape[i - shift] == 1 ? 0 : strides[i - shift]);
        return new Tensor(data, offset, newShape, st);
    }
}
```

по broadcastTo
```text
Старый тензор формы [2, 3]
Хотим привести к [1, 2, 3] → shift = 1
Оси сопоставляются так:
[1, 2, 3]
   [2, 3] ← старый тензор
То есть старые оси «прилипают» к концу, а слева добавляются новые.

oneRow имеет shape [1, 3], strides [3, 1]. Хотим broadcastTo(4, 3).
shift = 2 - 2 = 0 (rank не меняется);
ось 0: shape[0] == 1 → stride 0;
ось 1: shape[1] == 3, новая размерность 3 → stride 1.

Результат: shape [4, 3], strides [0, 1].
```

### Ещё более сложный пример

Это уже тот уровень, на котором тензор становится полезным для ML.
Есть element-wise операции с broadcasting и matmul. 

```java
import java.util.Arrays;

public class Tensor {
    final float[] data;
    final int offset;
    final int[] shape;
    final int[] strides;

    @FunctionalInterface   //чтобы binaryOp принимал лямбду без автобоксинга.
    public interface FloatOp { float apply(float a, float b); }

    public Tensor(int... shape) {
        this.data = new float[prod(shape)];
        this.offset = 0;
        this.shape = shape.clone();
        this.strides = canonical(shape);
    }

    private Tensor(float[] data, int offset, int[] shape, int[] strides) {
        this.data = data;
        this.offset = offset;
        this.shape = shape;
        this.strides = strides;
    }

    /** @return тензор из нулей заданной формы. */
    public static Tensor zeros(int... shape) { return new Tensor(shape); }

    // вернёт strides по shape 
    static int[] canonical(int[] s) {
        int[] r = new int[s.length];
        int a = 1;
        for (int i = s.length - 1; i >= 0; i--) { r[i] = a; a *= s[i]; }
        return r;
    }

    /** @return число логических элементов тензора. */
    public int size() { int n = 1; for (int x : shape) n *= x; return n;  }

    /**
     * Читает элемент по многомерному индексу:
     * {@code flat = offset + Σ idx[k] * strides[k]}.
     */
    public float get(int... i) {
        int f = offset;
        for (int k = 0; k < i.length; k++) f += i[k] * strides[k];
        return data[f];
    }

    /** Записывает элемент по многомерному индексу. */
    public void set(float v, int... i) {
        int f = offset;
        for (int k = 0; k < i.length; k++) f += i[k] * strides[k];
        data[f] = v;
    }

    /**
     * Транспонирование 2D — O(1) вью.
     * Меняет местами shape и strides, буфер и offset не трогает.
     */
    public Tensor transpose() {
        return new Tensor(data, offset, new int[]{shape[1], shape[0]}, new int[]{strides[1], strides[0]});
    }

    //Срез по одной оси
    public Tensor slice(int axis, int start, int end) {
        int[] s = shape.clone();
        s[axis] = end - start;
        return new Tensor(data, offset + start * strides[axis], s, strides);
    }

    /**
     * Broadcast-вью к заданной форме — O(1).
     * Ось, которую «растягиваем», получает stride = 0, и индекс по ней
     * «схлопывается» — читается один и тот же элемент буфера.
     */
    public Tensor broadcastTo(int... newShape) {
        int[] st = new int[newShape.length];
        int shift = newShape.length - shape.length;
        for (int i = 0; i < newShape.length; i++)
            st[i] = i < shift ? 0 : (shape[i - shift] == 1 ? 0 : strides[i - shift]);
        return new Tensor(data, offset, newShape, st);
    }

    public Tensor add(Tensor o) { return binaryOp(o, (a, b) -> a + b); }
    public Tensor sub(Tensor o) { return binaryOp(o, (a, b) -> a - b); }
    public Tensor mul(Tensor o) { return binaryOp(o, (a, b) -> a * b); }
    public Tensor div(Tensor o) { return binaryOp(o, (a, b) -> a / b); }

    /**
     * Поэлементная бинарная операция с broadcasting.
     *
     * <p>Алгоритм:
     * <ol>
     *   <li>вычислить итоговую форму через {@link #broadcastShape};</li>
     *   <li>привести обе стороны к этой форме через {@link #broadcastTo};</li>
     *   <li>пройти по плоскому индексу результата, восстановить
     *       многомерный idx и применить операцию.</li>
     * </ol>
     *
     * <p>Значения читаются через {@link #get(int...)}, поэтому stride = 0
     * на broadcast-осях учитывается корректно.
     */
    Tensor binaryOp(Tensor o, FloatOp op) {
        int[] outShape = broadcastShape(shape, o.shape);
        Tensor a = broadcastTo(outShape);
        Tensor b = o.broadcastTo(outShape);
        Tensor r = new Tensor(outShape);
        int[] idx = new int[outShape.length];
        for (int f = 0; f < r.data.length; f++) {
            int t = f;
            for (int i = outShape.length - 1; i >= 0; i--) { idx[i] = t % outShape[i]; t /= outShape[i]; }
            r.data[f] = op.apply(a.get(idx), b.get(idx));
        }
        return r;
    }

    /**
     * Broadcast-форма двух форм по правилу NumPy: выравнивание
     * по правому краю, размер 1 растягивается до размера другой стороны.
     * 
     broadcastShape(new int[]{4, 3}, new int[]{3})   // -> [4, 3]
     broadcastShape(new int[]{2, 1, 4}, new int[]{3, 4}) // -> [2, 3, 4]
     broadcastShape(new int[]{5}, new int[]{1})      // -> [5]

     Зачем нужна. В binaryOp мы должны сначала узнать форму результата, чтобы потом создать тензор r этой формы и привести к ней обе стороны
     */
    static int[] broadcastShape(int[] shape1, int[] shape2) {
        int rank = Math.max(shape1.length, shape2.length);
        int[] newShape = new int[rank];
        for (int i = 0; i < rank; i++) {
            int shape1_i = i < rank - shape1.length ? 1 : shape1[i - (rank - shape1.length)];
            int shape2_i = i < rank - shape2.length ? 1 : shape2[i - (rank - shape2.length)];
            newShape[i] = Math.max(shape1_i, shape2_i);
        }
        return newShape;
    }

    /**
     * Матричное умножение 2D: [M, K] × [K, N] -> [M, N].
     *
     * <p>Работает для не-contiguous входов: чтение идёт через
     * {@link #get(int...)}, который учитывает strides и offset.
     * Порядок циклов i, k, j выбран ради кэш-дружественности:
     * во внутреннем цикле читается строка B и пишется строка C.
     *
     * <p>Проверка совместимости форм не делается — это минимальная версия.
     */
    public Tensor matmul(Tensor o) {
        int M = shape[0], K = shape[1], N = o.shape[1];
        Tensor r = new Tensor(M, N);
        for (int i = 0; i < M; i++)
            for (int k = 0; k < K; k++) {
                float aik = get(i, k);
                for (int j = 0; j < N; j++) r.data[i * N + j] += aik * o.get(k, j);
            }
        return r;
    }

    @Override
    public String toString() {
        return "Tensor" + Arrays.toString(shape) + ", offset=" + offset + ", strides=" + Arrays.toString(strides) + ", size=" + size();
    }
}
```

- broadcastShape отвечает на вопрос «какая форма»
- broadcastTo — на вопрос «дай мне тензор этой формы».


- broadcastShape — как калькулятор: «если сложить матрицу 4×3 и вектор длины 3, какая форма получится?» → «4×3».
- broadcastTo — как резиновая плёнка: «растяни этот вектор длины 3 на 4 строки, чтобы он подошёл к матрице».


Что имеет смысл добавить дальше:
- Проверку границ и ошибки
- isContiguous / contiguous. Для реализации reshape
- reshape. Чтобы можно было менять форму без копии.
- ML-операции: sum / mean / softmax
- Активации: relu / sigmoid
- замена get/set во всех операциях на прямые индексы для скорости

Strides и offset — это про представление, не про семантику. add, matmul, softmax как функции работают одинаково. 
Меняется то, что transpose/slice/broadcast теперь не копируют память.

С strides приходит флаг «contiguous». 
Как только у вас появились вью, каждая «плоская» операция должна либо требовать contiguous, либо уметь ходить по strides. 
Отсюда и contiguous() как обязательный шаг перед BLAS-подобными вещами.
