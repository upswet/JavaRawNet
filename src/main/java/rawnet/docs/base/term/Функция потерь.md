# Функция потерь (loss function)

**Функция потерь (loss function)** — это мера того, насколько сильно предсказания модели отличаются от истинных целевых значений на обучающих примерах. Именно её значение используется для обновления весов сети в процессе обучения: мы стремимся найти такие параметры модели, которые минимизируют среднее значение функции потерь по всей обучающей выборке.
Собственно весь процесс обучения это и есть уменьшение функции потерь.
Другими словами то, чему и как быстро обучится ваша нейросеть определяется одной только функцией потерь.

Зачем нам вообще нужна какая-то особая функция потерь? Почему ею не может быть обычная «целевое_значение – значение_выданное_нейросетью)?
Ну ладно, не такую вот прямо просто, а хотя бы её значение по модулю (иначе ошибки в большую сторону и в меньшую сторону по разным нейронам рискуют выдать среднее значение функции потерь в ноль, как будто нейронка ответила идеально правильно. Открою секрет – можно использовать и такую. МАЕ называется.

В алгоритме обучения требуется градиент функции потерь, который бы обнулялся в точке идеального соответствия целевого значения и значения выданного нейросетью.

Вы спросите, что такое этот ваш «градиент»? 

Мы отвечаем: [градиент](../math/Математический%20анализ.md#градиент) – это вектор частных производных. 

Другими словами если у вас есть функция многих переменных f(x1, x2, x3…) то градиентом по ней будет вектор составленный из всех частных производных, то есть (df/dx1, df/dx2, df/dx3…). Каждая компонента показывает, как быстро меняется функция при изменении соответствующей переменной, когда остальные зафиксированы. Вместе они задают направление наискорейшего роста функции.

Ещё раз, чтобы запомнить:\
**Производная функции** – скорость изменения функции\
**Частная производная функции** – скорость изменения функции при изменении одной конкретной переменной, при условии, что остальные переменные считаются константами.\
**Градиент** – вектор составленный из всех частных производных функции (по каждой из её переменных). Это направление наискорейшего роста функции. Это чувствительность, то есть ответ на вопрос «если я чуть-чуть изменю входное значение, то насколько сильно изменится итоговое значение функции.

Ещё раз\
Производная - скорость роста функции.\
Градиент - направление этого роста (или чувствительность - крутизна скорости роста)

В нейросетях [градиент говорит](../math/Математический%20анализ.md#градиентный-спуск), в какую сторону менять каждый вес, чтобы loss уменьшился.

```java
/**Интерфейс функции потерь*/
public interface Loss extends Serializable {
    /**
     * Вычислить потерю
     * @param predicted выходной вектор (output нейросети)
     * @param target целевой вектор (какой должен быть выход)
     * @return потеря на данном примере (средняя потеря по всем нейронам выходного слоя)
     */
    float loss(float[] predicted, float[] target);

    /**
     * Вычислить производную функции потери
     * @param predicted выходной вектор (output нейросети)
     * @param target целевой вектор (какой должен быть выход)
     * @param deriv вектор производных
     */
    void derivative(float[] predicted, float[] target, float[] deriv);
}
```

Виды функий потерь:

## Среднеквадратичная ошибка (MSE)

функция $L_{\text{MSE}} = \frac{1}{N} \sum_{i=1}^N (\hat{y}_i - y_i)^2$ 

производная $\quad \frac{\partial L_{\text{MSE}}}{\partial \hat{y}_i} = \frac{2}{N}(\hat{y}_i - y_i) \approx \hat{y}_i - y_i$

Сильно штрафует большие ошибки.

Предполагает, что ошибки не зависят от значения функции (то есть если чем больше значение, тем больше возможная ошибка (как процент от значения), то mse использовать не надо. 
В этом случае используйте MAE

Чувствительна к аномальным выбросам – модель может сильно исказиться, пытаясь учесть единичные некорректные измерения. Но если таковых нет, то всё ок (как раз наш случай).
Производная mse = 2/N  * (y~ - y) или просто y~ - y (то есть: ответ_нейросети - целевое_значение) так как нам требуется только направление для алгоритма обучения нейросети (в какую сторону менять веса)

>В коде мы опускаем 2/N, считая его частью lr; но помните, что при добавлении регуляризации масштаб градиента меняется

```java
/**
 * Среднеквадратичная ошибка (MSE):
 * loss = (1/N) * Σ(pred_i - target_i)^2.
 * derivative = pred - target
 *
 * Сильные стороны: гладкая, выпуклая, штрафует большие ошибки сильнее (квадратично), градиент линеен по ошибке. Хорошо подходит для задач регрессии.
 *
 * Слабые стороны: чувствительна к выбросам, может доминировать.
 *
 * Рекомендуемое сочетание: выходной слой с Linear активацией (без нелинейности).
 * При использовании с сигмоидой/softmax может приводить к медленному обучению из-за насыщения.
 */
public class Mse implements Loss {
    public float loss(float[] p, float[] t) {
        float s = 0;
        for (int i = 0; i < p.length; i++) {
            float d = p[i] - t[i];
            s += d * d;
        }
        return s / p.length;
    }

    public void derivative(float[] p, float[] t, float[] d) {
        for (int i = 0; i < p.length; i++)
            d[i] = p[i] - t[i];
    }
}
```

## Средняя абсолютная ошибка (MAE)

функция $L_{\text{MAE}} = \frac{1}{N} \sum_{i=1}^N |\hat{y}_i - y_i| $

производная $ \quad \frac{\partial L_{\text{MAE}}}{\partial \hat{y}_i} = \begin{cases} \frac{1}{N}, & \hat{y}_i > y_i, \\ -\frac{1}{N}, & \hat{y}_i < y_i. \end{cases} \approx \begin{cases} 1, & \hat{y}_i > y_i, \\ -1, & \hat{y}_i < y_i. \end{cases} $

Как раз для случаев если у нас в наборе данных полно разных «выбросов».

Или если «шум» зависит от самого значения функции (например если в выборке данных по цене продажи квартир ошибка в цене для обычных квартир примерно 100 тыс, а ошибка для люксовых домов уже 1 млн – то есть ошибка зависит от самого значения функции).

На практике при реализации градиентного спуска часто опускают множитель
1
/
N
1/N или считают, что он включён в скорость обучения, поэтому говорят, что градиент MAE — это просто знак ошибки (1 или -1) - то есть направление которое и нужно нам для алгоритма обучения

```java
/**
 * Средняя абсолютная ошибка (MAE):
 * loss = (1/N) * Σ|pred_i - target_i|
 * derivative = 1 если pred > target, -1 если pred < target и 0 если pred = target
 *
 * Сильные стороны: менее чувствительна к выбросам, чем MSE, градиент постоянен по знаку (±1).
 *
 * Слабые стороны:градиент не зависит от величины ошибки, может медленнее сходиться вблизи оптимума; не дифференцируема в нуле (здесь возвращается 0).
 *
 * Рекомендуемое сочетание: выходной слой с Linear, реже с другими.
 */
public class Mae implements Loss {
    public float loss(float[] p, float[] t) {
        float s = 0;
        for (int i = 0; i < p.length; i++) s += Math.abs(p[i] - t[i]);
        return s / p.length;
    }

    public void derivative(float[] p, float[] t, float[] d) {
        for (int i = 0; i < p.length; i++) {
            float diff = p[i] - t[i];
            d[i] = diff > 0 ? 1 : diff < 0 ? -1 : 0;
        }
    }
}
```

## Huber Loss

Гибрид, объединяющий преимущества MSE (гладкость вблизи нуля) и MAE (устойчивость к выбросам).

$
\begin{equation}
L_\delta(a) =
\begin{cases}
\frac{1}{2}a^2, & \text{если } |a| \leq \delta, \\
\delta\left(|a| - \frac{1}{2}\delta\right), & \text{если } |a| > \delta,
\end{cases}
\end{equation}
a = \hat{y} - y .
$

$\frac{\partial L_\delta}{\partial a} = \begin{cases} a, & |a| \leq \delta, \\ \delta, & a > \delta, \\ -\delta, & a < -\delta. \end{cases}$

При малых ошибках (\(|a| \leq \delta\)) ведёт себя как MSE (сильный градиент, быстрая сходимость).\
При больших ошибках (\(|a| > \delta\)) переходит в линейный режим MAE, уменьшая влияние выбросов.\
Параметр \(\delta\) определяет границу переключения; его можно настраивать или фиксировать (например, \(\delta = 1.0\)).


## Как выбирать функцию потерь для регрессии?

Базовый выбор – MSE. Хорошо работает, когда данные чистые, выбросов мало, а шум можно считать гауссовым.

При наличии выбросов переходят на MAE или Huber Loss.

## Categorical crossentropy
Категориальная кросс-энтропия — это функция потерь для многоклассовой классификации, когда каждый объект принадлежит ровно одному из C классов. 
Она измеряет, насколько предсказанное распределение вероятностей отличается от истинного.

$$ L = -\sum_{i=1}^{C} y_i \log(p_i) $$
- y_i— истинная метка
- p_i - предсказанная вероятность класса i
- C — число классов

Если y_i задаётся как one-hot вектор то все y_i, кроме правильного класса, равны 0, и формула упрощается: $ L = -log(p_y)$
где p_y это предсказанная вероятность правильного класса

Функция сильно штрафует модель за уверенные неправильные ответы.
То есть чем меньше вероятность, которую модель дала правильному классу, тем больше потеря. При этом штраф растёт нелинейно: за уверенную ошибку модель наказывается особенно сильно.

Связь с [softmax](Функция активации.md#softmax)

Важное свойство: если объединить Softmax и categorical crossentropy, градиент по логитам получается очень простым:
$$ \frac{\partial L}{\partial z_i} = p_i - y_i $$
Это одна из причин, почему такая пара так популярна.

```java
/**
 * Перекрёстная энтропия (Cross-Entropy) для многоклассовой классификации.
 * Ожидает на входе вероятности после Softmax. loss = -Σ target_i * log(pred_i). Вектора должны быть one-hot
 *
 * Сильные стороны: в сочетании с Softmax даёт простой и эффективный градиент dL/dz = pred - target
 * (после объединения производной Softmax и кросс-энтропии), что решает проблему замедления обучения
 * сигмоиды на выходе. Стандарт для классификации (но только если объект может принадлежать строго одному классу)
 * .
 * Слабые стороны: численная нестабильность, если pred близко к 0 (используется epsilon).
 *
 * Рекомендуемое сочетание: только строго с Softmax на последнем слое.
 */
public class CrossEntropy implements Loss {
    private static final float EPS = 1e-15f;

    public float loss(float[] p, float[] t) {
        float s = 0;
        for (int i = 0; i < p.length; i++)
            s -= t[i] * Math.log(Math.max(p[i], EPS));
        return s;
    }

    /**
     * Производная кросс-энтропии по выходу Softmax.
     * В комбинации с backward SoftmaxLayer (который пропускает градиент как есть)
     * итоговый градиент по логитам будет d = pred - target.
     */
    public void derivative(float[] p, float[] t, float[] d) {
        for (int i = 0; i < p.length; i++) d[i] = p[i] - t[i];
    }
}
```

Эта производная, в мтеоде derivative предполагает, что перед ней стоит Softmax, и возвращает dL/dz, а не dL/dp как то требуется.

Разновидности
+ CategoricalCrossentropy — метки в виде one-hot векторов, выходной слой с Softmax.
+ SparseCategoricalCrossentropy — то же самое, но метки заданы целыми числами: 0, 1, 2, … Экономит память и удобнее, когда классов много.
+ BinaryCrossentropy — для двух классов, выходной слой с Sigmoid, метки 0 или 1.

### Binary Cross Entropy

$$ L_{\text{BCE}} = -\left( y \cdot \log(p) + (1 - y) \cdot \log(1 - p) \right) $$

Здесь y — истинная метка (0 или 1), p — предсказанная моделью вероятность того, что пример относится к классу 1.

```java
/**BCE математически предполагает, что каждый элемент target — это вероятность Бернулли, т.е. 0 или 1
 *
 * Бинарная кросс-энтропия для многомерного выхода (многометочная классификация).
 * loss = - Σ [target_i * log(pred_i) + (1 - target_i) * log(1 - pred_i)].
 * Предполагается, что каждый выход независимо проходит через сигмоиду.
 *
 * Сильные стороны: корректная вероятностная интерпретация, быстрый градиент при использовании
 * с сигмоидой (dL/dz = pred - target) при условии объединённой производной.
 *
 * Слабые стороны: если считать производную по pred как (pred - target) / (pred * (1 - pred)),
 * возможна численная нестабильность около 0 и 1. В данной реализации используется именно эта формула,
 * которая корректна только в комбинации с последующей производной сигмоиды в Dense слое,
 * что в итоге даёт градиент pred - target. Следует избегать вызова derivative в отрыве от слоя сигмоиды.
 *
 * <b>Рекомендуемое сочетание:выходной слой строго с Sigmoid-ой.
 */
public class BinaryCrossEntropy  implements Loss {
    private static final float EPS = 1e-15f;

    public float loss(float[] p, float[] t) {
        float s = 0;
        for (int i = 0; i < p.length; i++)
            s -= t[i] * Math.log(Math.max(p[i], EPS)) + (1 - t[i]) * Math.log(Math.max(1 - p[i], EPS));
        return s / p.length; // усреднение по размерности
    }

    /**
     * Производная бинарной кросс-энтропии по вероятности pred.
     * В паре с Sigmoid (derivative = out*(1-out)) полный градиент по z будет (pred - target).
     */
    public void derivative(float[] p, float[] t, float[] d) {
        for (int i = 0; i < p.length; i++) {
            d[i] = (p[i] - t[i]) / Math.max(p[i] * (1 - p[i]), EPS);
        }
    }
}
```

### Focal Loss (бинарная)

Проблема, которую она решает. 
Представьте детектор, который ищет объекты на изображении, где 99% пикселей — фон, а 1% — объекты. 
Обычная Binary Cross-Entropy (BCE) штрафует каждую ошибку одинаково. 
Сеть быстро понимает, что «предсказывать везде 0» даёт accuracy 99%, и перестаёт учиться находить объекты. 
Формально loss падает, а модель бесполезна.

Focal Loss (Lin et al., 2017) меняет штраф так, чтобы лёгкие примеры почти не влияли, а всё внимание уходило на трудные:

Focal Loss — это модификация BCE. Она добавляет два дополнительных параметра, чтобы сместить фокус обучения:

$L = -\alpha_t \cdot (1 - p_t)^\gamma \cdot \log(p_t)$

- pt — вероятность правильного класса: p⋅y+(1−p)⋅(1−y). Если сеть уверена и права, pt →1; если уверена и ошибается, pt →0.
- αt — вес класса: (для положительного а) α * y + (1+a) * (1-y). Для отрицательного 1- a
- γ — сила фокусировки. При  γ=0 формула вырождается в BCE. Стандарт γ=2


Что делает (1 - p_t)^γ:
- Если сеть уверена и права (p_t → 1), множитель (1 - p_t)^γ → 0 — loss гасится. Фон с p = 0.01 имеет p_t = 0.99 (для t=0), (1 - 0.99)² = 10⁻⁴ — вклад почти ноль.
- Если сеть ошибается (p_t → 0), множитель (1 - p_t)^γ → 1 — loss полный. Пиксель-пик с p = 0.1 имеет p_t = 0.1, (1 - 0.1)² = 0.81 — вклад почти полный.

Что делает α_t:
- Балансирует фон/пики по «важности». α = 0.25 → фон весит 0.75, пики 0.25. Пики — «редкие, но важные», их вклад усиливается относительно фона.
- Требование α ∈ [0,1], иначе α_t для одной из групп станет отрицательным, и loss уйдёт в минус (классическая ловушка, см. ниже).

α — весовой коэффициент для балансировки классов (часто выбирают обратно пропорционально частоте класса)

Когда что выбирать?
- Выбирайте BCE, если классы в вашем датасете сбалансированы, и вам не нужно специально акцентировать внимание на каких-то особых, редких случаях. BCE проще, вычислительно эффективнее и в таких сценариях работает отлично.
- Выбирайте Focal Loss, если у вас сильно несбалансированный датасет или если для вас критически важно хорошо ловить редкие случаи. Однако учтите: если редкий класс сильно зашумлён (много ошибок в разметке), чрезмерный фокус на таких примерах может ухудшить обобщающую способность модели.

Существует другой вариант Focal Loss — для heatmap-подхода (CenterNet, CornerNet), где метки мягкие (гауссианы). 
Это не то же самое, что бинарная Focal Loss. Если вы делаете детекцию по heatmap — используйте CenterNetFocalLoss, а не BinaryFocalLoss. Смешивать их нельзя: BinaryFocalLoss на мягких метках даст неправильный loss.

```java
public class BinaryFocalLoss implements Loss {
    private static final float EPS = 1e-7f;
    private float alpha;
    private float gamma;

    public BinaryFocalLoss() { this(0.25f, 2f); }

    public BinaryFocalLoss(float alpha, float gamma) {
        if (alpha < 0f || alpha > 1f)
            throw new IllegalArgumentException("alpha must be in [0, 1]");
        if (gamma < 0f)
            throw new IllegalArgumentException("gamma must be >= 0");
        this.alpha = alpha;
        this.gamma = gamma;
    }

    @Override
    public float loss(float[] p, float[] t) {
        double s = 0;
        for (int i = 0; i < p.length; i++) {
            float pi = Math.max(Math.min(p[i], 1f - EPS), EPS);
            float ti = t[i];
            float pt = pi * ti + (1f - pi) * (1f - ti);
            float at = alpha * ti + (1f - alpha) * (1f - ti);
            s -= at * Math.pow(1 - pt, gamma) * Math.log(Math.max(pt, EPS));
        }
        return (float) (s / p.length);
    }

    @Override
    public void derivative(float[] p, float[] t, float[] d) {
        for (int i = 0; i < p.length; i++) {
            float pi = Math.max(Math.min(p[i], 1f - EPS), EPS);
            float ti = t[i];
            float pt = pi * ti + (1f - pi) * (1f - ti);
            float at = alpha * ti + (1f - alpha) * (1f - ti);
            float sign = 2f * ti - 1f;               // d(pt)/dp
            float oneMinusPt = Math.max(1f - pt, EPS);

            // dL/dp = at * sign * (term1 - term2)
            float term1 = gamma
                    * (float) Math.pow(oneMinusPt, gamma - 1f)
                    * (float) Math.log(Math.max(pt, EPS));
            float term2 = (float) Math.pow(oneMinusPt, gamma) / pt;

            d[i] = at * sign * (term1 - term2);
        }
    }
}
```

## One-hot вектор
Это способ представления категориальных данных (например, слов или признаков) в виде числового вектора, где каждое значение соответствует определённой категории.

Допустим, у нас есть словарь из 5 цветов: [«красный», «зелёный», «синий», «жёлтый», «серый»]

Тогда их one-hot представление будет таким:
+ «красный» → [1, 0, 0, 0, 0]
+ «зелёный» → [0, 1, 0, 0, 0]
+ «синий» → [0, 0, 1, 0, 0]
+ «жёлтый» → [0, 0, 0, 1, 0]
+ «серый» → [0, 0, 0, 0, 1]

## Шпаргалка по выбору
| Задача | Лосс | Выходной слой | Примечание |
| --- | --- | --- | --- |
| Классификация (1 из N) | SoftmaxCrossEntropy | DenseLayer (Linear, N нейронов) | Классы взаимоисключающие. Softmax внутри лосса. |
| Мульти-метка (несколько классов одновременно) | BinaryCrossEntropy | DenseLayer + Sigmoid, N нейронов | Каждый класс — независимая бинарная задача. |
| Бинарная классификация | BinaryCrossEntropy | DenseLayer + Sigmoid, 1 нейрон |  |
| Семантическая сегментация | BinaryCrossEntropy (или SoftmaxCrossEntropy) | Conv (1×1) + Sigmoid (или Linear) | BCE, если один объект может принадлежать нескольким классам (или фон+объекты). Softmax, если классы строго взаимоисключающие. |
| Детекция: Heatmap (CenterNet) | FocalLoss | Conv (1×1) + Sigmoid | Сильный дисбаланс фона и пиков (99.9% vs 0.1%). BCE тут «схлопнется» в предсказание нулей. |
| Детекция: Grid (YOLO) | GridDetectionLoss (кастом) | Conv (1×1) + Sigmoid | BCE для obj и классов, L1/MSE — только для bbox в заполненных ячейках. |
| Детекция: регрессия bbox | Mae (L1) или Huber | Conv/Dense (Linear) | Для координат w, h, cx, cy. Устойчивее к выбросам, чем MSE. |
| Регрессия (выбросов нет) | Mse | Linear | Стандартный выбор для непрерывных значений. |
| Регрессия (выбросы важны) | Mae / Huber | Linear |  |

## Антипаттерны (чего избегать)
| Комбинация | Почему это плохо | Что делать вместо |
| --- | --- | --- |
| Mse + Sigmoid (для вероятностей) | Градиент затухает на краях [0,1]: dL/dz = (p - t) · p(1-p). При p → 0 или p → 1 множитель p(1-p) убивает градиент. Сеть «застревает» в уверенно неправильных ответах. | BinaryCrossEntropy (или BinaryFocalLoss при дисбалансе). |
| Mae + Sigmoid (для вероятностей) | MAE оптимизирует медиану, а не вероятность. Градиент ±1 не учитывает, насколько предсказание далеко от метки, и плохо калибрует вероятности. | BinaryCrossEntropy / BinaryFocalLoss. |
| Mse для классификации | Бессмысленно: класс 4 не «в 4 раза больше» класса 1. Расстояние между классами не имеет смысла, а MSE его «измеряет». | CrossEntropy (softmax) или BinaryCrossEntropy (multi-label). |
| Mae для классификации | Градиент ±1 не учитывает вероятность, сходимость хаотична. Модель «дёргается» между классами. | CrossEntropy. |
| BinaryCrossEntropy без Sigmoid | BCE ожидает вероятности в [0,1], а Linear выдаёт логиты (-∞..+∞). log от отрицательного числа = NaN, от >1 — тоже NaN. | Либо Sigmoid + BCE, либо слитый слой BCEWithLogits (стандарт в PyTorch — численно устойчивее). |
| CrossEntropy без Softmax | CrossEntropy.derivative возвращает p - t, предполагая, что p — после Softmax. Если подать логиты, градиент будет неверным (и log может дать NaN). | Либо Softmax + CE, либо слитый слой SoftmaxCrossEntropy (стандарт). |
| BinaryFocalLoss для сбалансированных классов | Избыточно: гасит лёгкие примеры, которых и так мало. Обучение замедляется без выигрыша в качестве. | Обычная BinaryCrossEntropy. |
| BinaryFocalLoss на мягких метках (гауссианах) | p_t в классической Focal Loss определён для жёстких меток y ∈ {0,1}. На мягких метках формула даёт неправильный loss: окрестности центра штрафуются как обычный фон. | CenterNetFocalLoss (с параметром β и весом (1-y)^β). |
| Huber + Sigmoid (для вероятностей) | Huber — для регрессии (устойчивость к выбросам в непрерывных значениях). На вероятностях он не даёт вероятностной интерпретации. | BinaryCrossEntropy / BinaryFocalLoss. |
| Mse + Softmax (для классификации) | Softmax + MSE даёт медленный градиент (как sigmoid + MSE): p(1-p) фактор в softmax-якобиане гасит сигнал. | SoftmaxCrossEntropy — градиент p - t, простой и быстрый. |
| Loss с регуляризацией, но lr подобран без неё | L2-штраф добавляется к градиенту (∂L/∂w = ∂L_data/∂w + 2λw), и эффективный масштаб градиента меняется. lr, подобранный без регуляризации, может «взорвать» обучение. | Подбирать lr после включения регуляризации. Или использовать AdamW (decoupled weight decay), где lr и λ независимы. |
| BinaryCrossEntropy с EPS = 1e-15f (и подобное) | 1e-15f для float — субнормальное число. 1 - 1e-15f округляется до 1.0f, и клиппинг сверху не работает. p = 1.0f → log(0) → NaN. | EPS = 1e-7f (безопасно для float). |
| CrossEntropy / BinaryCrossEntropy без max-трюка в Softmax/Sigmoid | exp(1000) = Infinity, log(0) = -Infinity. Один аномальный логит — и весь батч даёт NaN. | Вычитать максимум из логитов до exp: exp(z - max(z)). Или использовать слитые слои SoftmaxCrossEntropy / BCEWithLogits, где трюк уже встроен. |
| Mae в точке p = t | Производная MAE в нуле не определена. В коде обычно возвращают 0 — это безопасно, но замедляет сходимость ровно в оптимуме. | Для гладкости — Huber (квадратичен вблизи нуля, линеен вдали). |
| Mse с выбросами в данных | Квадрат ошибки делает выбросы доминирующими: одна аномалия с ошибкой 100 даёт вклад 10000, и модель «подстраивается» под неё в ущерб остальным. | Mae или Huber — устойчивы к выбросам. |
| BinaryFocalLoss(alpha=0.5, gamma=2) на сбалансированных данных | alpha=0.5 отключает балансировку, но gamma=2 всё равно гасит лёгкие примеры. На сбалансированных данных это только замедляет обучение. | BinaryCrossEntropy. |
| alpha > 1 или alpha < 0 в BinaryFocalLoss | α_t для одной из групп становится отрицательным, и loss уходит в минус. Классическая ловушка. | alpha ∈ [0, 1]. Проверять в конструкторе. |
| gamma < 0 в BinaryFocalLoss | (1 - p_t)^γ при p_t → 1 даёт 0^отрицательное = Infinity. Градиент «взрывается». | gamma >= 0. Проверять в конструкторе. |


## Быстрый выбор по типу выхода сети

- Выход Sigmoid (вероятности): BinaryCrossEntropy, FocalLoss.
- Выход Softmax (вероятности): SoftmaxCrossEntropy (или CrossEntropy).
- Выход Linear (любые числа): Mse, Mae, Huber.

| Выходной слой | Задача | Лосс |
| --- | --- | --- |
| Linear | Регрессия (чистые данные) | Mse |
| Linear | Регрессия (выбросы) | Mae / Huber |
| Sigmoid (1 нейрон) | Бинарная классификация | BinaryCrossEntropy |
| Sigmoid (1 нейрон) | Бинарная классификация с дисбалансом | BinaryFocalLoss |
| Sigmoid (N нейронов) | Multi-label (несколько классов одновременно) | BinaryCrossEntropy |
| Softmax (N нейронов) | Многоклассовая (1 из N) | SoftmaxCrossEntropy |
| Sigmoid (heatmap) | Детекция (CenterNet) | CenterNetFocalLoss |


Правило: лосс и выходной слой — парные сущности. CrossEntropy требует Softmax, BinaryCrossEntropy требует Sigmoid, Mse/Mae/Huber требуют Linear. 
Нарушение пары — самая частая причина «loss не падает» или NaN.

## Loss не падает — что делать

Симптом: значение loss стоит на месте, колеблется вокруг константы или падает на первых шагах и застревает. 
Действуйте сверху вниз.

- Проверьте gradient check. Если аналитический градиент не совпадает с численным — дальше искать бессмысленно.
- Проверьте знак обновления. Спуск должен идти против градиента: w -= lr * grad. Плюс вместо минуса — loss растёт или стоит. Это ошибка №1.
- Слишком большой lr. Loss «дёргается», уходит вверх или в NaN. Уменьшите в 10 раз и проверьте.
- Слишком маленький lr. Loss падает, но микроскопически. Увеличьте в 3–10 раз (осторожно, см. п.3).
- Мёртвые активации. Sigmoid/ReLU в насыщении: все выходы 0 или 1, градиент ~0. Проверьте распределение активаций по слоям.
- Неправильная пара «лосс + активация». См. таблицу антипаттернов: Mse + Sigmoid, BCE + Linear — сеть будет «стоять». Сверьтесь со шпаргалкой по выбору.
- Данные. Перепутаны predicted и target местами; метки не в том формате (классы 0..N-1 вместо one-hot); все примеры одного класса; признаки не нормализованы (для регрессии с MSE — критично).
- Инициализация. Все веса нули → все нейроны учатся одинаково. Нужна случайная инициализация (Xavier/He).
- Регуляризация душит. Слишком большой коэффициент L2 может перевесить data-loss. Временно отключите — loss должен начать падать.
- Проверьте на одном примере (overfit sanity check). Возьмите 1–2 примера и попробуйте переобучить сеть до почти нулевого loss. Если не получается — баг в коде (backward, обновление весов, лосс), а не в данных или гиперпараметрах.
