# Оптимизатор

Это “правило”, по которому нейросеть исправляет свои веса на основе ошибки

Цикл следующий:
- Модель делает предсказание
- Считается ошибка (loss)
- Вычисляются градиенты loss по параметрам
- Оптимизатор обновляет параметры
- Шаги повторяются

```java
/**Интерфейс оптимизатора*/
public interface Optimizer extends Serializable {
    /**
     * Обновляет веса и смещения по их градиентам.
     *
     * @param weights    матрица весов размера [число нейронов][число входов]
     * @param weightGrad градиенты весов той же размерности
     * @param biases     вектор смещений размера [число нейронов]
     * @param biasGrad   градиенты смещений
     * @param batchSize  размер батча, по которому накоплены градиенты;
     *                   используется для усреднения градиента
     */
    void update(float[][] weights,
                float[][] weightGrad,
                float[] biases,
                float[] biasGrad,
                int batchSize);
}
```


## SGD
Стохастический градиентный спуск.

Простейший вариант.

Из минусов: медленно ползёт по «оврагам» когда в одном направлении производная большая, а в другом маленькая.

```
w = w - lr * grad
```

$$
w_{\text{new}} = w_{\text{old}} - \eta \cdot \frac{\partial L}{\partial w}
$$

$$
b_{\text{new}} = b_{\text{old}} - \eta \cdot \frac{\partial L}{\partial b}
$$


```java
/**
 * Стохастический градиентный спуск (SGD).
 * <p>
 * Простейший оптимизатор: параметр сдвигается в сторону,
 * противоположную усреднённому градиенту:
 * <pre>
 *   param = param - lr * grad / batchSize
 * </pre>
 * Состояния между шагами не хранит.
 */
@RequiredArgsConstructor
public class SGD implements Optimizer {
    private final float lr;

    @Override
    public void update(float[][] weights, float[][] weightGrad, float[] biases, float[] biasGrad, int batchSize) {
        float scale = lr / batchSize;

        for (int i = 0; i < weights.length; i++) {
            for (int j = 0; j < weights[i].length; j++) {
                weights[i][j] -= scale * weightGrad[i][j];
            }
            biases[i] -= scale * biasGrad[i];
        }
    }
}
```



## Momentum

Добавляет инерцию, как тяжёлый шар, катящийся по ландшафту.

Идея: накапливается скорость v, и градиент используется не напрямую, а для изменения скорости.

```text
v_new = β · v_old + g              // g = ∇L(w), средний по батчу
w_new = w - lr · v_new

Обычно β = 0.9   управляет инерцией независимо от learning rate
v — «чистая» скорость
```

Если градиент долго направлен в одну сторону, скорость растёт — быстрее проходим пологие участки.
Это заметно ускоряет обучение, особенно на зашумлённых градиентах

```java
/**
 * SGD с импульсом (Momentum).
 * <p>
 * Кроме текущего градиента хранит "скорость" — экспоненциально
 * сглаженную историю градиентов:
 * <pre>
 *   v = momentum * v + grad / batchSize
 *   param = param - lr * v
 * </pre>
 * Импульс помогает быстрее проходить вдоль устойчивых направлений
 * и гасить колебания в поперечных направлениях.
 */
@RequiredArgsConstructor
public class Momentum implements Optimizer {
    /** Скорость обучения. */
    private final float lr;

    /** Коэффициент импульса, обычно 0.9. */
    private final float momentum;

    /**
     * Скорости для весов. Ключ — сам массив весов, поэтому используется
     * IdentityHashMap: состояние привязано к конкретному объекту-параметру.
     * поэтому при пересоздании слоя оно автоматически „сбрасывается“; это же позволяет одному оптимизатору обслуживать несколько слоёв.
     */
    private final Map<float[][], float[][]> weightVelocity = new IdentityHashMap<>();
    /** Скорости для смещений. */
    private final Map<float[], float[]> biasVelocity = new IdentityHashMap<>();

    @Override
    public void update(float[][] weights, float[][] weightGrad, float[] biases, float[] biasGrad, int batchSize) {
        // Получаем или создаём буферы скорости для данного слоя.
        float[][] wv = weightVelocity.computeIfAbsent(weights, k -> new float[weights.length][weights[0].length]);
        float[] bv = biasVelocity.computeIfAbsent(biases, k -> new float[biases.length]);

        // Усредняем градиент по батчу.
        float scale = 1f / batchSize;

        for (int i = 0; i < weights.length; i++) {
            for (int j = 0; j < weights[i].length; j++) {
                float g = weightGrad[i][j] * scale;
                float v = momentum * wv[i][j] + g; // накопленная скорость
                wv[i][j] = v;
                weights[i][j] -= lr * v;  // шаг по скорости
            }

            float gb = biasGrad[i] * scale;
            float vb = momentum * bv[i] + gb;
            bv[i] = vb;
            biases[i] -= lr * vb;
        }
    }
}
```

## NAG
Nesterov Accelerated Gradient (NAG) — модификация Momentum, которая «смотрит вперёд»: градиент берётся не в текущей точке, а в точке, где мы окажемся, если продолжим движение по инерции.

Канонический NAG
```text
v_new = β · v_old + lr · ∇L(w - β · v_old)
w_new = w - v_new

Смысл: градиент берётся в точке будущего положения w - β·v_old, а не в текущей w.
```
Отличие от моментума только в той точке где считаем градиент. 
Моментум - в текущей точке. Nag - в точке где мы окажемся если продолжим движение по инерции.
Это даёт более раннее торможение при смене направления, чем обычный Momentum: если впереди «стена», NAG замедлится ещё до того, как в неё врежется.

Пробный шаг требует вычислять градиент в другой точке — это дорого(нужен отдельный forward/backward). 
На практике используют эквивалентную переформулировку, где градиент берётся в текущей точке w (как обычно), а «взгляд вперёд» учитывается добавкой β·v_new:
```text
v_new = β · v_old + g
w_new = w - lr · (g + β · v_new)

здесь g — градиент в текущей точке, а β·v_new — «добавка инерции»

Это та же самая формула, что и выше, только lr вынесен за скобку,а v — «чистая» накопленная скорость (без lr внутри)

buf = momentum * buf + grad          # v_new
d = grad + momentum * buf            # g + β·v_new
param -= lr * d
```

```text
Momentum:  v_new = β · v_old + g;   w_new = w - lr · v_new
NAG:       v_new = β · v_old + g;   w_new = w - lr · (g + β · v_new)
```

```java
/**
        * Nesterov Accelerated Gradient (NAG).
        * <p>
 * Модификация Momentum с "взглядом вперёд": сначала делается шаг по
 * накопленной скорости, а градиент как бы берётся в точке будущего положения.
        * В используемой форме обновление выглядит так:
        * <pre>
 *   g = grad / batchSize
 *   v = momentum * v + g
 *   d = g + momentum * v
 *   param = param - lr * d
 * </pre>
        * Это даёт более раннее торможение при смене направления по сравнению
 * с обычным Momentum.
 */
@RequiredArgsConstructor
public class NAG implements Optimizer {
    private final float lr;
    private final float momentum;

    private final Map<float[][], float[][]> weightVelocity = new IdentityHashMap<>();
    private final Map<float[], float[]> biasVelocity = new IdentityHashMap<>();

    @Override
    public void update(float[][] weights, float[][] weightGrad, float[] biases, float[] biasGrad, int batchSize) {
        // Получаем или создаём буферы скорости для данного слоя.
        float[][] wv = weightVelocity.computeIfAbsent(weights, k -> new float[weights.length][weights[0].length]);
        float[] bv = biasVelocity.computeIfAbsent(biases, k -> new float[biases.length]);

        float scale = 1f / batchSize;

        for (int i = 0; i < weights.length; i++) {
            for (int j = 0; j < weights[i].length; j++) {
                float g = weightGrad[i][j] * scale;
                // Обычное накопление скорости.
                float v = momentum * wv[i][j] + g;
                wv[i][j] = v;

                // Nesterov-поправка: добавляем ещё один импульс от новой скорости.
                float d = g + momentum * v;
                weights[i][j] -= lr * d;
            }

            float gb = biasGrad[i] * scale;
            float vb = momentum * bv[i] + gb;
            bv[i] = vb;

            float db = gb + momentum * vb;
            biases[i] -= lr * db;
        }
    }
}
```

## Adam
Adam (Adaptive Moment Estimation)

Идея на пальцах

Представь, что ты спускаешься с горы в тумане. Ты не видишь весь маршрут, но чувствуешь под ногами уклон. Обычный градиентный спуск делает шаг в сторону уклона, причём шаг одинаковый для всех направлений. Это может быть медленно и дёргано.

Adam делает умнее:

Смотрит, куда ты уже шёл.
Если несколько шагов подряд уклон был в одну сторону, Adam как бы разгоняется — появляется инерция. Это называется первый момент или momentum.

Смотрит, насколько сильно уклон менялся.
Если в каком-то направлении градиент постоянно большой и скачет, Adam делает шаг осторожнее. Если градиент маленький и стабильный — шаг может быть больше. Это второй момент, идея из RMSProp.

Для каждого веса — свой шаг.
В обычном SGD один learning rate для всех параметров. Adam подстраивает эффективный шаг отдельно для каждого веса. Поэтому он хорошо работает, когда разные параметры ведут себя по-разному.

Не тормозит на старте.
В начале обучения средние значения ещё «пустые», и Adam делает поправку, чтобы первые шаги не были слишком маленькими. Это называют bias correction.

```text
m = β1 * m + (1 - β1) * grad
v = β2 * v + (1 - β2) * grad²
m_hat = m / (1 - β1^t)
v_hat = v / (1 - β2^t)
w = w - lr * m_hat / (sqrt(v_hat) + ε)
Стандартные значения: β1 = 0.9, β2 = 0.999, ε = 1e-8.
```
m — первый момент (сглаженный градиент),
v — второй момент (сглаженный квадрат градиента),

bias correction через 1 − βt

В обычном Adam если добавить L2 weight decay то добавлять их прямо в градиент: grad = ∇L + λ * w

Устойчив, быстр, хорошо работает без тонкой настройки гиперпараметров.

## AdamW

```text
m = β₁ * m + (1 - β₁) * grad
v = β₂ * v + (1 - β₂) * grad²
m_hat = m / (1 - β₁^t)
v_hat = v / (1 - β₂^t)
w = w - lr * m_hat / (sqrt(v_hat) + ε) - lr * λ * w

grad — чистый градиент функции потерь, без L2-добавки,
λ — коэффициент decoupled weight decay,
lr — learning rate,
t — номер шага, начиная с 1.

β₁ = 0.9
β₂ = 0.999
ε = 1e-8
λ = 0.01   (иногда 0.05 или 0.1)
lr = 1e-3  (для общих задач) или 3e-4 (для трансформеров)
```

bias correction через 1 − βt  (Weight decay не применяют к bias )

Лучший вариант, но, как и стандартный адам - требует больше памяти.

Отличия AdamW от Adam в том, что он не позволяет весам разрастаться (тянет веса к нулю)

```java
/**
 * AdamW — Adam с раздельным (decoupled) weight decay.
 * <p>
 * Хранит первые и вторые моменты градиентов:
 * <pre>
 *   m = beta1 * m + (1 - beta1) * g
 *   v = beta2 * v + (1 - beta2) * g^2
 * </pre>
 * Затем применяет bias correction:
 * <pre>
 *   mHat = m / (1 - beta1^t)
 *   vHat = v / (1 - beta2^t)
 *   update = mHat / (sqrt(vHat) + eps)
 *   w = w - lr * (update + weightDecay * w)
 * </pre>
 * Weight decay применяется только к весам и не применяется к bias.
 */
@RequiredArgsConstructor
public class AdamW implements Optimizer {
    private final float lr;     //Скорость обучения
    private final float beta1;  //Экспоненциальное затухание для первого момента
    private final float beta2;  //Экспоненциальное затухание для второго момента.
    private final float eps;    //Малая константа для численной устойчивости
    private final float weightDecay; //Коэффициент L2-штрафа (weight decay).  Способ регуляризации модели, который «наказывает» её за слишком большие значения весов. Его цель — не дать модели переобучиться, сделав её более устойчивой к шуму в данных.

    private final Map<float[][], float[][]> mW = new IdentityHashMap<>();   //Первые моменты для весов
    private final Map<float[][], float[][]> vW = new IdentityHashMap<>();   //Вторые моменты для весов
    private final Map<float[], float[]> mB = new IdentityHashMap<>();       //Первые моменты для смещений
    private final Map<float[], float[]> vB = new IdentityHashMap<>();       //Вторые моменты для смещений
    private final Map<Object, Integer> steps = new IdentityHashMap<>();     //Номера шагов для bias correction; ключ — массив параметров

    public AdamW(float lr) {
        this(lr, 0.9f, 0.999f, 1e-8f, 0.01f);
    }

    @Override
    public void update(float[][] weights, float[][] weightGrad, float[] biases, float[] biasGrad, int batchSize) {
        // Получаем или создаём состояния для весов и смещений
        float[][] mw = mW.computeIfAbsent(weights, k -> new float[weights.length][weights[0].length]);
        float[][] vw = vW.computeIfAbsent(weights, k -> new float[weights.length][weights[0].length]);
        float[] mb = mB.computeIfAbsent(biases, k -> new float[biases.length]);
        float[] vb = vB.computeIfAbsent(biases, k -> new float[biases.length]);

        // Увеличиваем счётчики шагов отдельно для весов и bias.
        int stepW = steps.merge(weights, 1, Integer::sum);
        int stepB = steps.merge(biases, 1, Integer::sum);

        float bc1W = (float) (1 - Math.pow(beta1, stepW));
        float bc2W = (float) (1 - Math.pow(beta2, stepW));
        float bc1B = (float) (1 - Math.pow(beta1, stepB));
        float bc2B = (float) (1 - Math.pow(beta2, stepB));

        float scale = 1f / batchSize;

        for (int i = 0; i < weights.length; i++) {
            for (int j = 0; j < weights[i].length; j++) {
                float g = weightGrad[i][j] * scale;

                // Обновляем первый и второй моменты для веса.
                mw[i][j] = beta1 * mw[i][j] + (1 - beta1) * g;
                vw[i][j] = beta2 * vw[i][j] + (1 - beta2) * g * g;

                float mHat = mw[i][j] / bc1W;
                float vHat = vw[i][j] / bc2W;

                // Адаптивный шаг.
                float update = mHat / (float) (Math.sqrt(vHat) + eps);

                // weight decay применяется к весам
                weights[i][j] -= lr * (update + weightDecay * weights[i][j]);
            }

            float gb = biasGrad[i] * scale;

            mb[i] = beta1 * mb[i] + (1 - beta1) * gb;
            vb[i] = beta2 * vb[i] + (1 - beta2) * gb * gb;

            float mHatB = mb[i] / bc1B;
            float vHatB = vb[i] / bc2B;

            float updateB = mHatB / (float) (Math.sqrt(vHatB) + eps);

            biases[i] -= lr * updateB; // bias обычно без weight decay
        }
    }
}
```

## Шпаргалка по выбору оптимизатора

| Хочу… | Беру… |
| --- | --- |
| Полный контроль, воспроизводимость | SGD (+ schedule) |
| Быстрый старт «из коробки» | AdamW |
| Регуляризацию без хитрой настройки | AdamW (weight decay) |
| Проверенный baseline для сравнения | SGD + Momentum |


Для гиперпараметров

| Параметр | Значение | Комментарий |
| --- | --- | --- |
| batchSize | 16–32 | 1 — плохо, >128 — нужен больший LR |
| lr для SGD | 0.01 | При увеличении batch — масштабировать |
| lr для AdamW | 0.001 | Адаптивный, много не надо |
| Эпох | 30–100 | Лучше с early stop по метрике |


## Learning rate schedule

Скорость обучения lr — самый важный гиперпараметр оптимизатора. И почти всегда её полезно менять по ходу обучения, а не держать константой.

Интуиция: в начале обучения веса далеко от оптимума, и большие шаги безопасны и полезны. Ближе к концу мы уже рядом с минимумом — большие шаги заставляют «прыгать» вокруг него и мешают сойтись. Поэтому lr обычно уменьшают к концу.

- Step decay — уменьшаем lr в k раз каждые N эпох: lr(t) = lr0 * gamma^(t / step)
- Cosine annealing — плавно уменьшаем по косинусу от lr0 до почти нуля: lr(t) = lr_min + 0.5 * (lr0 - lr_min) * (1 + cos(pi * t / T))
- Warmup + decay — сначала увеличиваем lr с нуля до lr0 за несколько сотен/тысяч шагов, потом уменьшаем (cosine или linear). Warmup критичен для трансформеров: на первых шагах градиенты шумные, и большой lr сразу «убивает» обучение.

```java
/** Простейшее расписание: lr зависит от номера эпохи. */
public interface LrSchedule {
    float lr(int epoch, int totalEpochs, float baseLr);
}

/** Step decay: каждые step эпох lr умножается на gamma. */
public class StepDecay implements LrSchedule {
    private final int step;
    private final float gamma;
    public StepDecay(int step, float gamma) { this.step = step; this.gamma = gamma; }

    @Override
    public float lr(int epoch, int totalEpochs, float baseLr) {
        return baseLr * (float) Math.pow(gamma, epoch / step);
    }
}

/** Cosine annealing: плавно от baseLr до ~0. */
public class CosineDecay implements LrSchedule {
    private final float minLr;
    public CosineDecay(float minLr) { this.minLr = minLr; }

    @Override
    public float lr(int epoch, int totalEpochs, float baseLr) {
        float t = (float) epoch / Math.max(1, totalEpochs);
        return minLr + 0.5f * (baseLr - minLr) * (1f + (float) Math.cos(Math.PI * t));
    }
}

/** Warmup + cosine: первые warmupEpochs линейно растём, потом cosine. */
public class WarmupCosine implements LrSchedule {
    private final int warmupEpochs;
    private final float minLr;
    public WarmupCosine(int warmupEpochs, float minLr) {
        this.warmupEpochs = warmupEpochs;
        this.minLr = minLr;
    }

    @Override
    public float lr(int epoch, int totalEpochs, float baseLr) {
        if (epoch < warmupEpochs) {
            return baseLr * (epoch + 1) / (float) warmupEpochs;
        }
        float t = (float) (epoch - warmupEpochs) / Math.max(1, totalEpochs - warmupEpochs);
        return minLr + 0.5f * (baseLr - minLr) * (1f + (float) Math.cos(Math.PI * t));
    }
}
```

Ну или можно запускать обучение несколько раз последовательно с разным коэффициентом обучения.

Практическое правило: если не хочется думать — берите cosine decay с lr0, подобранным под оптимизатор. На большинстве задач это даёт больше, чем выбор между SGD и Adam при фиксированном lr.

## Gradient clipping

При обучении RNN и трансформеров градиенты иногда «взрываются»: одна аномальная точка данных даёт огромный градиент, и один шаг оптимизатора разрушает веса, накопленные за часы.

Gradient clipping — простое лечение: если норма градиента (по всем параметрам) больше порога maxNorm, масштабируем её вниз до порога, сохраняя направление:
```text
if ||g|| > maxNorm:
    g = g * maxNorm / ||g||
```

Это не меняет направление шага — только его длину. Типичные значения maxNorm: 1.0 или 5.0.
```java
    private static void applyClip(double gradNormSq, FloatConsumer scaleGrad,
                                  float clipNorm, int actualBatch) {
        if (clipNorm <= 0f) return;
        double norm = Math.sqrt(gradNormSq);
        double threshold = (double) clipNorm * actualBatch;
        if (norm > threshold) {
            scaleGrad.accept((float) (threshold / norm));
        }
    }
```

## Сколько памяти ест оптимизатор

| Оптимизатор | Доп. память | Что хранит |
| --- | --- | --- |
| SGD | O(1) | ничего |
| Momentum | O(P) | скорость v |
| NAG | O(P) | скорость v |
| Adam | O(2P) | m и v |
| AdamW | O(2P) | m и v |

Плюс сами параметры (P) и градиенты (P) — их хранят все. 
То есть Adam/AdamW в пике требуют примерно 4×P чисел с плавающей точкой против 2×P у SGD.

Для сети на 100M параметров во float32:
- SGD: параметры + градиенты ≈ 800 МБ
- AdamW: параметры + градиенты + m + v ≈ 1.6 ГБ

Почему у SGD lr порядка 0.1–0.01, а у Adam — 1e-3–1e-4? Потому что Adam нормирует шаг на оценку стандартного отклонения градиента:
```text
update = m_hat / (sqrt(v_hat) + eps)
```

При увеличении batch size, lr для SGD обычно масштабируют линейно (lr *= k при batch *= k) — это linear scaling rule; 
для Adam это правило работает хуже, и часто просто оставляют lr как есть или масштабируют по квадратному корню.

> Практическое правило: начинайте с lr = 0.01 для SGD+Momentum и lr = 1e-3 для AdamW. Если loss растёт — уменьшайте в 3–10 раз. Если loss падает слишком медленно — увеличивайте, но осторожно.
