## Задача ассоциативного поиска

Задача: ассоциативный поиск (associative recall, mini-словарь).

Задача ассоциативного поиска — это следующий шаг после long-range copy и delayed summation. 
Если те задачи проверяли «донести один бит» или «дождаться двух событий», то ассоциативный поиск проверяет «запомнить несколько пар и найти нужную по ключу». 
Это уже ближе к реальной памяти (словарь, база данных, кэш)

```text
Вход:    k₀ → v₀    k₁ → v₁    k₂ → v₂    k₃ → v₃, query  
Выход:   vᵢ, где kᵢ = query

Входная последовательность длиной 2*PAIRS + 1 токенов:
    PAIRS позиций с ключами
    PAIRS позиций со значениями (идут парами key→value)
    Последняя позиция — query


3→5    1→7    4→2    0→6    query=4    →    2
```

Почему задача сложна для RNN
- Проблема «бутылочного горлышка». Простая RNN сжимает всю последовательность в один h[T]. Для P = 4 это 8 токенов пар + query = 9 шагов. h[T] должен содержать: все 4 пары (8 чисел), информацию о том, какой ключ был в какой паре, и всё это — в одном векторе фиксированной размерности.
- Проблема «забывания». Простая RNN забывает начало. Если query в конце, а нужная пара — в начале, RNN «не донесёт» её.
- Проблема «адресации». Даже если RNN запомнил все пары, нужно найти нужную по ключу. Это не «взять среднее» (как в delayed summation), а «сравнить query с каждым ключом и выбрать». Простая RNN не умеет «сравнивать» — она умеет только «суммировать».
