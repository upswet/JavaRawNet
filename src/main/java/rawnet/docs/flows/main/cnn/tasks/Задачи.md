## Задачи нахождения объектов на картинке

Класс задач где нужно найти объекты на изображениях. 

[ImageDatasetGenerator.java](imageDetect/ImageDatasetGenerator.java) — генератор данных и целевых меток

Один пример — квадратная картинка S×S, белый фон, 0..maxObjects непересекающихся фигур (CIRCLE, SQUARE, CROSS, TRIANGLE) случайного размера и цвета из палитры.
- Генерирует картинки — рандомные фигуры без пересечений.
- Строит targets — статические методы под каждую задачу, независимые от картинки.

Типы
- ShapeInstance — описание объекта: тип, центр, полуразмеры, цвет. Содержит удобные left()/right()/top()/bottom()/bounds().
- LabeledSample — пример: картинка + список объектов + таргет + плоский RGB-вход.
- Task (перечисление типов детекции объектов на картинке) — DETECTION / GRID / HEATMAP / SEMSEG.

Методы
- generateOne(Task) / generate(count, Task) — генерирует пример и сразу строит для него target нужного формата.
- toFlatRgb(BufferedImage) — перевод картинки в плоский тензор flat(3*S*S) в [0,1], раскладка [R(все), G(все), B(все)] (channel-major) — именно так её ждут свёрточные слои.
- Методы подтговтки target (ожидаемого ответа) в соответствии с задачей
  - Задача детеккции объектов на картинке
    - buildDetectionTargets — multi-label flat(4): 0/1 по классам.
  - Задача определения объектов на картинке
    - buildGridTargets — YOLO-раскладка flat(G·G·(5+C)): в каждой ячейке [obj, cx_local, cy_local, w, h, onehot(C)]; cx/cy нормированы в ячейку, w/h — в размер картинки.
    - buildHeatmapTargets — CenterNet: flat(C·S·S) с гауссианами в центрах объектов, пики разных объектов берутся через max (не суммируются).
    - buildSemsegTargets — попиксельный one-hot flat((C+1)·S·S), канал 0 — фон.
- inside(ShapeInstance, x, y) — проверка «внутри фигуры» (эллипс/прямоугольник/треугольник/крест) — нужна для корректной семантической маски.
- toSimple(List) — мостик к SampleDataset.

формат ответа диктует архитектуру: DETECTION — плоский выход, GRID и HEATMAP — пространственный, SEMSEG — попиксельный.

Функции потери для задачи определения объектов на изображении

Три файла (для трёх различных подходов (см ниже) к решению задачи определения объектов на изображении) — GridLoss, HeatmapLoss, SegLoss — реализуют три разные постановки задачи детекции через три разные функции потерь

[GridLoss.java](imageDetect/loss/GridLoss.java) — YOLO-style, ячейки сетки

Постановка. 
Картинка делится на G×G ячеек; в каждой ячейке сеть предсказывает 5+C чисел: obj (есть ли объект), cx_local, cy_local (центр внутри ячейки, [0,1)), w, h (размеры относительно картинки), one-hot(C) по классам. 
Выход — flat((5+C)·G·G) в channel-major раскладке (сначала все ячейки канала obj, потом все cx, и т.д.) — именно так лежит cnn(5+C, G, G) в памяти.

Составная функция потери
- obj: BCE по всем ячейкам, с разными весами для занятых (λ_obj) и пустых (λ_noobj) — классический приём, чтобы фон не «задавил» редкие объекты; нормируется на nObj.
- box: MSE по cx, cy и по √w, √h (корень — чтобы большие и маленькие объекты давали сравнимый градиент); только в занятых ячейках; нормируется на cells.
- class: softmax-CE по каналам 5..5+C-1; только в занятых; нормируется на cells.

Это самый «многосоставный» loss в разделе и лучший пример того, что функция потерь — это дизайн, а не формула из учебника.

[HeatmapLoss.java](imageDetect/loss/HeatmapLoss.java) — CenterNet-style, focal loss по гауссианам

Постановка. 
Выход — flat(C·S·S) логитов: по каналу на класс, в каждом пикселе — «вероятность, что здесь центр объекта данного класса».
Target — мягкие гауссианы вокруг центров (см. buildHeatmapTargets). 
Задача — не «попасть в пиксель», а дать острый пик в центре и почти нули вокруг.

loss(logits, target) — focal loss:
- positive (t > 0.99): −(1−p)^α · log(p) — если пик не уверен, штраф сильный;
- negative (иначе): −(1−t)^β · p^α · log(1−p) — чем ближе t к 1 (т.е. чем ближе пиксель к центру), тем слабее штраф за ложную активацию; это и есть «focusing»: сеть не тратит ёмкость на «полу-фон» вокруг объекта.
- Нормировка на N_pos (число пикселей с t > 0.99) — как в оригинале CenterNet.

Focal loss — главный «трюк» CenterNet, и здесь видно, почему он нужен: на картинке 128×128 с 4 объектами положительных пикселей единицы, а отрицательных — десятки тысяч; обычная BCE «утонет» в фоне. 
Параметр β управляет «прощением» к околопиковым ошибкам, α — балансом positive/negative. 
Полезно сравнить с GridLoss: там та же проблема решается через λ_noobj, здесь — через фокусный множитель.

[SegLoss.java](imageDetect/loss/SegLoss.java) — попиксельная softmax-CE для семантической сегментации

Постановка. 
Выход — flat(C·S·S) логитов (канал 0 — фон, каналы 1..C — фигуры). 
Target — one-hot на каждый пиксель. 
Задача — классифицировать каждый пиксель независимо от других.

Это самый «чистый» loss в наборе — по сути, обычная softmax-CE, применённая к каждому пикселю отдельно. Он полезен как точка отсчёта: видно, что задачи HEATMAP и SEMSEG отличаются не только loss'ом, но и что считается ответом — «центр» vs «каждый пиксель». Заодно сравнение с HeatmapLoss показывает, зачем нужен focal-множитель: без него CE на 99% фона даёт почти нулевой градиент по объектам.

### Задача детекции объектов

Простейший вид задачи определения объектов. 
Надо просто ответить на вопрос присутствует ли на изображении объект заданного вида или нет.

Постановка. На вход подаётся изображение, на выходе — вектор из C чисел, по одному на каждый класс объектов.
Значение 1 означает «объект этого класса на картинке присутствует», 0 — «отсутствует».
Геометрия (где именно находится объект) не предсказывается — только факт присутствия.

Это ближайший аналог обычной классификации, только классов может быть несколько одновременно.
Если в задаче классификации выход — softmax над C классами (ровно один правильный), то здесь выход — C независимых sigmoid-вероятностей (каждый класс — свой бинарный классификатор).
Это и есть multi-label.

### Задача определения объектов

На вход — изображение.
На выходе — набор объектов, для каждого: класс (CIRCLE/SQUARE/CROSS/TRIANGLE) и ограничивающий прямоугольник (cx, cy, w, h).
В отличие от простой детекции, здесь нужно ответить не только «что есть», но и «где именно», причём раздельно для каждого объекта (два круга — это два объекта, а не один класс «круг»).

Разные подходы к решению задачи:

| Характеристика | Семантическая сегментация | Heatmap-подход (CenterNet)                    | Grid-подход (YOLO) |
| --- | --- |-----------------------------------------------| --- |
| Что предсказывает сеть | Класс для каждого пикселя | Вероятность нахождения центра объекта в точке | Рамку и класс для каждой ячейки сетки |
| Разделение объектов одного класса | Нет (сливает в одну маску) | Да (каждый пик — отдельный объект)            | Да (разные ячейки могут отвечать за разные объекты) |
| Основной результат | Попиксельная маска классов | Тепловая карта с пиками‑центрами              | Набор ограничивающих рамок (bounding boxes) |
| Связь с детекцией | Вспомогательная задача (контекст, фон) | Прямой метод детекции (объекты как точки)     | Прямой метод детекции (объекты как рамки) |

##### Семантическая сегментация
«Что за класс у каждого пикселя?»

Семантическая сегментация решает задачу попиксельной классификации.
Нейросеть для каждого пикселя изображения предсказывает класс объекта, к которому он принадлежит (машина, дорога, человек, фон).

- Приоритет: Локализация. Сначала определяется, где находится объект, а затем — что это за объект.
- Результат: Карта сегментации, где каждый пиксель раскрашен в цвет своего класса.
- Ограничение для детекции: Этот подход не разделяет объекты одного класса. Если на изображении две машины стоят вплотную, сегментационная карта покажет одну общую область класса «машина», а не два отдельных объекта.

Уточнение задачи.
На вход — картинка S×S.
На выходе — маска S×S, где каждый пиксель отнесён к одному из C классов (или к фону).
4-е класса фигур (CIRCLE, SQUARE, CROSS, TRIANGLE), фон = «все каналы нули» в one-hot.
Формат targets — flat(C·S·S), раскладка [class0(S·S), class1(S·S), ...], каждый пиксель — one-hot.

##### Heatmap-подход
«Где находится центр объекта?»

Heatmap-подход представляет детекцию как задачу оценки тепловой карты (heatmap).
Нейросеть предсказывает не класс каждого пикселя, а вероятностное поле, где пики (максимумы) соответствуют центрам объектов

- Приоритет: Обнаружение объекта через его характерную точку (центр).
- Результат: Набор пиков на heatmap. Каждый пик соответствует одному объекту, что позволяет естественно разделять объекты одного класса.
- Дополнительно: Из каждого пика сеть одновременно регрессирует параметры рамки (ширину и высоту).

##### Grid-подход
«Какой объект в этой ячейке?»

Grid-подход (классический для одностадийных детекторов, таких как YOLO или SSD) накладывает на изображение фиксированную сетку.
Каждая ячейка сетки «отвечает» за обнаружение объекта, центр которого в неё попал.

- Приоритет: Дискретизация пространства для предсказания рамок.
- Результат: Для каждой ячейки сетки сеть предсказывает координаты рамки (bounding box) и класс объекта.
- Связь с сегментацией: Некоторые современные anchor-free детекторы (например, FCOS) концептуально близки к семантической сегментации, так как предсказывают класс и расстояние до границ рамки для каждой пространственной позиции (пикселя или точки на карте признаков).

## Задача переноса стилей с одной картинки на другую

Пусть у нас есть две картинки:
- Фото кошки
- Любая картина Ван Гога.

Мы хотим получить третью картинку: «кошка, нарисованная в стиле Ван Гога».
То есть, по форме она похожа на кошку (те же контуры, тот же объект), а по текстуре, цвету и стилю на картину Ван Гога.

Формально, наш выход, искомая третья картинка, должна по содержанию быть первой, а по стилю второй.

Две реализации одной идеи — переноса стиля по Гатису. 
Медленная оптимизирует пиксели одной картинки при замороженной CNN.
Быстрая обучает отдельную сеть-стилизатор.

[StyleOps.java](styleTransform/StyleOps.java) — математическое ядро

Чистые операции над тензорами признаков и их аналитические градиенты. Всё остальное — обвязка вокруг этих четырёх функций.

- contentLoss(out, content) — mean((F_out − F_content)²). Просто MSE по фичам: «сохранить то, что было».
- contentLossGrad(...) — 2·(F_out − F_content)/N. Стандартный градиент MSE.
- gram(shape, F) — матрица Грама G[c1][c2] = (1/HW)·Σ F[c1,h,w]·F[c2,h,w]. Ключевая идея: попарные корреляции каналов, усреднённые по пространству. Именно она кодирует «текстуру»: какие признаки встречаются вместе, независимо от их расположения. Реализация использует симметрию (c2 от c1), чтобы не считать дважды.
- gramLoss(Gout, Gstyle) — mean((G_out − G_style)²). MSE по матрицам Грама: «сделать текстуру похожей».
- gramLossGrad(Fout, Gout, Gstyle, shape, gradOut) — аналитический градиент по F_out: dL/dF[c,h,w] = (4/(C·C·HW))·Σ_{c'} (G_out[c,c'] − G_style[c,c'])·F_out[c',h,w]. Это самая нетривиальная формула в разделе — цепное правило через G = F·Fᵀ, где G зависит от F квадратично. Коэффициент 4 — потому что MSE по симметричной матрице даёт 2, и производная Грама даёт ещё 2 (по каждому из двух вхождений F). В учебнике это хороший повод разобрать вывод руками.
- Shape (record) — обёртка над TensorShape, проверяет CNN-форму и достаёт C, HW.

Весь Style Transfer — это четыре формулы, и они здесь в явном виде. 
«Перенос стиля» — не магия, а MSE по фичам + MSE по Граму, и что градиент Грама считается аналитически.

[SlowStyleTransfer.java](styleTransform/SlowStyleTransfer.java) — Gatys 2015, оптимизация пикселей

Классический алгоритм: веса CNN заморожены, оптимизируется сам выходной тензор output, инициализированный копией content.

transfer(cnn, content, style, contentLayer, styleLayers, alpha, beta, iterations, lr) — главный цикл:
- Считает contentFeatures один раз (эталон).
- Считает styleGram[k] для каждого стилевого слоя один раз (эталон).
- Инициализирует output = contentFlat.clone().
- На каждой итерации: forwardUpTo до maxLayer, content loss + style loss, backwardFrom от каждого слоя к пикселям, суммирует с весами α и β/|styleLayers|, шаг SGD по пикселям, клип в [0,1].


- Model.forwardUpTo(cnn, output, layer) и Model.backwardFrom(cnn, layer, grad) — обход модели до произвольного слоя вперёд и назад. Это тот самый механизм, который позволяет «взять фичи на слое 9» и «прогнать градиент от слоя 9 до пикселей», не трогая веса.
- Градиенты от разных слоёв суммируются в gradPixels с весами α и β. Это и есть взвешивание «что важнее — форма или текстура».
- Клип [0,1] после шага — потому что выход — RGB-картинка, а сеть ничем не ограничена.
- Лог раз в 50 итераций: content и style loss по отдельности — видно, как они «торгуются».

Это самый «честный» Style Transfer: никаких дополнительных сетей, только градиент по входу. 
Медленно (600 итераций = десятки секунд), зато видно, что картинка — это тоже параметры, и что backwardFrom — универсальный инструмент.

[StyleStylizer.java](styleTransform/StyleStylizer.java) — архитектура быстрой сети-стилизатора

Энкодер-декодер S: cnn(3,S,S) → cnn(3,S,S), который учится превращать любой вход в «вход в стиле».

- энкодер /2 → /4: Conv(16, k=3, s=2) → LeakyReLU → Conv(32, k=3, s=2) → LeakyReLU → Conv(64, s=1) → LeakyReLU → Conv(64, s=1) → LeakyReLU (bottleneck 32×32);
- декодер ×2 → ×2: Upsample(2) → Conv(32) → InstanceNorm → LeakyReLU → Upsample(2) → Conv(16) → InstanceNorm → LeakyReLU;
- голова: Conv(3, k=1) без активации.

Три архитектурных решения,
- Conv(stride=2) вместо MaxPool. MaxPool.backward пропускает градиент только в позицию максимума — фильтры, не выигравшие argmax, не учатся. Conv(stride=2) дифференцируема везде.
- InstanceNorm только в декодере. В энкодере она «вымывает» абсолютные значения (яркость/цвет), и content loss (MSE по фичам) становится бессмысленным. В декодере — наоборот, нормирует выход, не трогая форму.
- Без Sigmoid на выходе. Sigmoid насыщается и теряет градиент; клип [0,1] в тренере и в apply дешевле и не мешает обучению.

Пример того, что архитектура диктуется требованиями к градиенту, а не только к прямому проходу. MaxPool «нормален» для классификации, но плох для генеративных задач; InstanceNorm хорош для стиля, но вреден для content.

[StyleStylizerTrainer.java](styleTransform/StyleStylizerTrainer.java) — обучение быстрой сети

Учит модель на одну стилевую картинку; после обучения apply даёт стилизацию за один forward.

Адаптивный β.
```betaIt = beta * (1 + 3·(1 − progress))   // 4β в начале → β в конце```
В начале модель ещё близка к тождеству (y ≈ x), и content loss = 0 — это локальный минимум, из которого легко не выбраться. 
Завышенный β в начале «выталкивает» модель из тождества, а к концу β снижается, и модель стабилизирует форму. 
Это классическая проблема генеративных сетей — требуется динамически изменять гиперпараметры обучения.

[StyleDemo.java](styleTransform/StyleDemo.java) — точка входа и визуализация

```text
ImageDatasetGenerator ──┐
                        ▼
grid-cnn.bin ──►  (CNN-фичи)  ◄── StyleOps (content/gram loss + градиенты)
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
SlowStyleTransfer              StyleStylizerTrainer
(оптимизирует пиксели)         (оптимизирует веса S)
        │                               │
        ▼                               ▼
BufferedImage                  StyleStylizer.apply ──► BufferedImage
        │                               │
        └──────────► StyleDemo ◄────────┘
                          │
                          ▼
                   out/style/*.png
```

- StyleOps — общее ядро: одна и та же математика для обоих сценариев.
- SlowStyleTransfer и StyleStylizerTrainer — две стратегии оптимизации одной и той же цели: «что двигаем» — пиксели vs веса.
- StyleStylizer — архитектура быстрой сети; её решения (Conv(stride=2), InstanceNorm в декодере, без Sigmoid) продиктованы требованиями к градиенту.
- StyleDemo — визуальная обвязка, одинаковая для обоих сценариев.

Style Transfer — это не новая архитектура, а новый loss поверх уже обученной CNN. 
Меняя только loss и то, по чему берётся градиент, можно получить совершенно новое поведение сети. 
Медленный и быстрый варианты — две точки в пространстве компромиссов «качество / скорость / сложность»
