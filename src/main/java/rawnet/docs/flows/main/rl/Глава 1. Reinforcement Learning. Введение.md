# Глава 12. Reinforcement Learning: введение

## Чем RL отличается от supervised learning

В supervised learning учитель говорит правильный ответ: «это кот». Тысячи раз. 
Модель сравнивает свой выход с эталоном и исправляет ошибки.

В RL учитель говорит только «хорошо» или «плохо» — а как надо, догадайся сам. 
Ты не даёшь ребёнку инструкцию «согни левое колено на 30°». 
Ты ставишь его на ноги, он пробует, падает, встаёт — и через сотни попыток учится. 
Когда получается — хвалишь (награда). Когда падает — ничего (или боль от падения).

| Характеристика       | Supervised                          | RL                                   |
|----------------------|-------------------------------------|--------------------------------------|
| Данные               | (x, y) — правильный ответ            | (s, a, r) — только награда           |
| Loss                 | CE(π(x), y) — сравнить с ответом    | −log π(a) · G — поощрить хорошие действия |
| Учитель              | «правильный ответ»                  | «хорошо / плохо»                     |
| Исследование         | не нужно (ответ известен)           | необходимо (ответ неизвестен)        |
| Стабильность         | высокая                             | низкая (шум, credit assignment)      |
| Примеры              | классификация, перевод, LM           | игры, роботы, RLHF                   |


Ключевое отличие — исследование. В supervised ответ известен, и модель просто учится его выдавать. 
В RL правильного действия нет — есть только награда. 
Если агент всегда выбирает лучшее по текущей оценке, он никогда не попробует альтернативы и застрянет в локальном оптимуме. 
Поэтому агент сэмплирует действия из распределения, а не берёт argmax.

Сэмплировать (от англ. sample — «образец», «выборка») — значит выбрать случайно из набора, согласно вероятностям. Не взять лучшее, не взять первое, не взять по порядку — а «бросить кубик» и выбрать то, что выпало, с учётом того, насколько каждый вариант вероятен.

Supervised — «учитель знает ответ».

RL — «учитель знает только "хорошо/плохо"**, а как — догадайся».

## Три ключевых понятия

В RL всегда есть три вещи: агент, среда и награда.

**Агент (agent)**

Тот, кто действует.
В нашем случае — нейросеть (Functional), которая по наблюдению (float[]) выдаёт действие (int).

**Среда (environment)**

То, с чем агент взаимодействует.

Среда — это мир, в котором живёт агент. Она принимает действие и возвращает:
- новое наблюдение (float[]) — что агент видит после действия;
- награду (float) — насколько хорошо действие;
- флаг done (boolean) — закончился ли эпизод.

Примеры среды
- CartPole — тележка с шестом. Агент толкает влево/вправо, шест наклоняется. Задача — не дать упасть.
- GridWorld — сетка 5×5. Агент ходит вверх/вниз/влево/вправо, ищет цель. Задача — дойти.
- Шахматы — доска. Агент делает ход, соперник отвечает. Задача — поставить мат.

**Награда (reward)**

Число, которое говорит агенту, насколько хорошо он только что поступил.

Почему reward — это не «правильный ответ»? Потому что reward говорит «насколько хорошо», а не «что было бы правильно». Если агент пошёл влево и получил +1 — было ли вправо лучше? Мы не знаем. Reward не говорит, какое действие было бы оптимальным — он говорит только, что это действие принесло столько-то.

В supervised label y — это точный ответ: «это кот». В RL reward r — это оценка: «ты сделал хорошо на 0.7». Из неё нельзя вывести «правильное действие» — можно только сказать «это действие лучше, чем другие».

Ключевое: награда может быть редкой. В шахматах — только в конце партии. В CartPole — каждый шаг. RL работает в обоих случаях, но редкая награда — сложнее (агент долго не знает, что делать).

- CartPole: +1 за каждый шаг, пока шест не упал. Задача — максимизировать сумму (то есть дольше держать).
- GridWorld: +1, когда дошёл до цели, −1, когда упал в яму, 0 — за каждый шаг. Задача — дойти быстрее.
- Шахматы: +1 за победу, −1 за поражение, 0 — за каждый ход. Задача — выиграть.

## Эпизод

Эпизод — одна попытка агента, от начала до конца.

```text
1. Среда: reset() → начальное наблюдение s₀
2. Пока не done:
     a. Агент: a = π(s)        — выбрать действие по политике
     b. Среда: step(a) → (s', r, done)
     c. Агент: запомнить (s, a, r), обновить s = s'
3. Эпизод закончился. Агент: посчитать суммарную награду, обновить политику.
```

- CartPole: от старта (шест в равновесии) до падения (> 12°). Максимум 500 шагов.
- GridWorld: от старта до цели, ямы или лимита шагов.
- Шахматы: от начала партии до мата / ничьей.

## Политика

Политика π(a|s) — функция, которая по наблюдению s говорит, какое действие выбрать (или вероятность каждого действия). В нейросетевом варианте:
```text
π(a|s) = softmax(Dense(s))
```
выход — вероятности действий.

- CartPole: Dense(2) → softmax → [p_left, p_right].
- GridWorld: Dense(4) → softmax → [p_up, p_down, p_left, p_right].
- Шахматы: Dense(~4000) → softmax → вероятности всех ходов.

Почему softmax, а не argmax. Если агент всегда выбирает лучшее действие — он никогда не попробует другие. А вдруг они лучше? Нужно исследование: агент сэмплирует действие, а не берёт argmax. Это ключевое отличие RL от supervised.

Сэмплировать — выбрать случайно из набора, согласно вероятностям. Не взять лучшее, не взять первое, не взять по порядку — а бросить кубик и выбрать то, что выпало. 

## Два подхода к RL

В RL два семейства алгоритмов.

### Value-based (DQN, Q-learning)

Учат Q-функцию Q(s,a) — «сколько награды получу, если выберу a в s». 
Политика выводится из Q: π(s) = argmax_a Q(s,a).

- Плюс: стабильно (Q-learning сходится к оптимальному Q).
- Минус: только дискретные действия (argmax по всем a), не работает для непрерывных.

### Policy-based (REINFORCE, PPO)

Учат политику π(a|s) напрямую — вероятности действий. Q-функция не нужна. Действие сэмплируется из π.

- Плюс: работает для непрерывных действий (π — гауссово распределение, сэмплируем из него).
- Минус: нестабильно (высокая дисперсия), сходится к локальному оптимуму.

Policy gradient — семейство алгоритмов, которые учат политику π(a|s) напрямую, без промежуточной Q-функции. 
REINFORCE — простейший представитель 

## Почему RL сложен

Три фундаментальные проблемы.

1. Credit assignment — «какой ход привёл к победе?».
   В шахматах награда — только в конце (+1 или −1). Партия — 40 ходов. Какой из 40 привёл к победе? Все получают одинаковую награду. Агент не знает, что исправить.
   Решение: discount (γ < 1) — «ближайшая награда важнее далёкой». Но это не полностью решает проблему.
2. Exploration vs exploitation — «пробовать новое или делать лучшее?».  
   Если агент всегда делает лучшее (argmax) — застрянет в локальном оптимуме. Если всегда случайное — не научится.
   Решение: сэмплирование из softmax (всегда есть шанс выбрать не лучшее), или ε-greedy (с вероятностью ε — случайное).
3. Нестабильность — «шум в градиенте».
   Одна и та же политика может дать разную награду (среда случайна). Градиент скачет. Обучение нестабильно.
   Решение: baseline (вычесть среднюю награду), normalization (разделить на std), Actor-Critic (critic снижает дисперсию), PPO (clipped objective).

>baseline не меняет матожидание градиента, но уменьшает дисперсию (если b(s) близко к G, то G - b(s) меньше, и разброс меньше). 
> Это как «центрирование» данных: вычитание среднего не меняет среднее, но уменьшает разброс.

RLHF — Reinforcement Learning from Human Feedback
1. Pretrain — LM на тексте (как GPT).
2. Reward model — обучают на человеческих предпочтениях («этот ответ лучше»).
3. RL — политика (LM) учится максимизировать награду reward model.

Именно RLHF превращает GPT-3 (просто продолжает текст) в ChatGPT (отвечает на вопросы, отказывается от вредного).

##  Почему нельзя просто обучить нейросеть

В RL правильного действия нет. Есть только награда r — «насколько хорошо было действие», но не «какое действие было бы правильным». Если агент пошёл влево и получил +1 — было ли вправо лучше? Мы не знаем.

Наивно: loss = (action_pred - action_taken)². Но action_taken — это что сделал агент, а не «что было бы правильно». Если агент сделал плохое действие, а мы «обучаем» его к этому действию — мы закрепляем плохое поведение. Это не обучение, это самоподтверждение.

Нужно что-то вроде:  loss = -reward * log_prob(action_taken);   // если reward хороший — увеличить вероятность

Это уже policy gradient — градиент по log π(a|s), взвешенный наградой.

```text
Пример: π = [0.7, 0.2, 0.1] (действия 0, 1, 2), агент выбрал a=0, reward = +1.
loss = -1 · log(0.7) = -1 · (-0.36) = +0.36.

Градиент по логитам: ∂loss/∂logit[0] = -1 · (1 - 0.7) = -0.3
                   ∂loss/∂logit[1] = -1 · (-0.2) = +0.2
                   ∂loss/∂logit[2] = -1 · (-0.1) = +0.1

Градиентный шаг: logit[0] += lr · 0.3 (увеличить), logit[1] -= lr · 0.2 (уменьшить), ...
→ π[0] растёт, π[1], π[2] падают. «Хорошее действие становится вероятнее».

Если reward = -1 (плохо): loss = +1 · log(0.7) = -0.36.
Градиент: ∂loss/∂logit[0] = +1 · (1 - 0.7) = +0.3 → logit[0] -= lr · 0.3 (уменьшить).
→ π[0] падает. «Плохое действие становится менее вероятным».
```

Если можем сразу оценить, что стало лучше — обучаем почти как supervised. Это contextual bandit — RL без временных шагов. Один шаг, одна награда.

Если не можем сразу — делаем несколько ходов и оцениваем скопом. 
Это REINFORCE с T > 1. 
Собираем траекторию (s_0, a_0, r_0, …, s_T) и считаем loss = −Σ G_t · log π(a_t|s_t).

Где G_t — это return (суммарная дисконтированная награда)
```text
G_t = r_t + γ·r_{t+1} + γ²·r_{t+2} + ... + γ^{T-t}·r_T = Σ_{t'=t}^{T} γ^{t'-t} · r_{t'}

r_t — награда, полученная на шаге t (сразу после действия a_t);
γ — дисконт (0 < γ ≤ 1), насколько агент ценит будущее;
T — последний шаг эпизода.

Смысл: G_t — «сколько всего награды я получу начиная с шага t и до конца эпизода», с учётом того, что далёкая награда важнее меньше, чем близкая.
```

Откуда сложность:
- Дисперсия G_t огромна. Решение: baseline — вычесть среднее.
- log π — это не «обучение нейросети». В supervised loss = (y_pred − y)² градиент напрямую сдвигает y_pred к y. В policy gradient loss = −G · log π(a|s) градиент увеличивает log π для действий с высоким G и уменьшает для низких. Это другая операция: «сделай вероятность действия a больше/меньше, в зависимости от G». Это обучение распределения, а не выхода. Отсюда softmax, log, сэмплирование — не «сложность ради сложности», а необходимость, потому что выход — это вероятности.
- Clip, entropy bonus, GAE — это уже инженерия: clip (PPO) ограничивает шаг политики; entropy bonus не даёт политике стать детерминированной слишком рано; GAE снижает дисперсию advantage умнее, чем G_t − V(s_t).

Почему детерминированная политика — это плохо? Потому что если π(a|s) = [1, 0, 0] (всегда выбирает действие 0), то агент никогда не попробует действия 1 и 2. Если действие 0 — локальный оптимум, агент застрянет. Entropy bonus (+ β · H(π)) поощряет политику быть менее уверенной, то есть сохранять исследование. Это как «не закрывай дверь, вдруг за ней лучше».

## Контракты: среда и тренер

Контракт среды — Environment
```java
public interface Environment {
    float[] reset();                    // начать эпизод → начальное наблюдение
    StepResult step(int action);        // шаг → (наблюдение, награда, done)
    int numActions();                   // сколько действий доступно
    int observationSize();              // длина вектора наблюдения

    record StepResult(float[] observation, float reward, boolean done) {}

    default void render() {}            // для отладки: напечатать состояние
}
```

reset() — начало эпизода. Среда сбрасывает состояние и возвращает начальное наблюдение. Вызывается один раз в начале и ещё раз после done == true.

step(action) — шаг. Среда принимает действие и возвращает новое наблюдение, награду и флаг done. После done == true нельзя вызывать step снова — сначала reset().

numActions() — сколько действий доступно. Нужно, чтобы создать выход политики: Dense(numActions). CartPole — 2, GridWorld — 4, шахматы — ~4000.

observationSize() — длина вектора наблюдения. Нужно, чтобы создать вход политики: InputDto(observationSize). CartPole — 4, GridWorld — 25, шахматы — ~800.

StepResult — record с тремя полями. Неизменяемый, среда создаёт новый на каждый шаг.

render() — опционально, для отладки. CartPole рисует тележку и шест, GridWorld — сетку.

Почему наблюдение — плоский float[]. Functional принимает плоский float[]. Среда возвращает вектор, агент сразу подаёт его в сеть — никаких преобразований. Для визуальных сред (Atari) это будет развёрнутое изображение; для CartPole — 4 числа.

Контракт тренера — RlTrainer
```java
public interface RlTrainer {
    void trainIteration();       // одна итерация: собрать данные, обновить политику
    RlMetrics lastMetrics();     // метрики итерации (для логов и early stopping)
}

public record RlMetrics(
        float avgReward,          // средняя награда за итерацию (эпизод или rollout)
        float avgEpisodeLength,   // средняя длина эпизода (шаги)
        float policyLoss,         // loss политики (для логов)
        float valueLoss,          // loss critic (NaN для REINFORCE)
        float entropy,            // средняя энтропия политики
        int episodes              // число эпизодов в итерации
) {
    public static RlMetrics reinforce(float avgReward, float avgEpisodeLength,
                                      float policyLoss, float entropy, int episodes) {
        return new RlMetrics(avgReward, avgEpisodeLength, policyLoss,
                Float.NaN, entropy, episodes);
    }
}
```

trainIteration() — одна итерация. 
Для REINFORCE — один эпизод (Monte-Carlo). 
Для PPO — один rollout (N шагов среды). 
Для DQN — один эпизод + обучение на replay buffer. 
Что именно считать итерацией — решает тренер, не вызывающий код.

Чем отличается «эпизод» от «rollout»? Эпизод — это полная попытка (от reset() до done). Rollout — это фиксированное число шагов (N), которое может быть меньше эпизода. REINFORCE использует полный эпизод, потому что ему нужна суммарная награда G_t (а она известна только в конце). PPO использует rollout (N шагов), потому что ему не нужна полная траектория — он обновляет политику чаще, на каждом rollout, и это стабильнее.

lastMetrics() — метрики итерации. Вызывается после trainIteration(). Нужны для логов и early stopping.

## Обёртка RlTraining
```java
public float train() {
    Deque<Float> rewardWindow = new ArrayDeque<>(window);
    float bestAvg = Float.NEGATIVE_INFINITY;
    int stale = 0;

    for (int it = 0; it < maxIterations; it++) {
        trainer.trainIteration();
        RlMetrics m = trainer.lastMetrics();

        // NaN-защита: policyLoss, entropy, avgReward — обязательные.
        // valueLoss — опциональное (NaN = «не применимо» для REINFORCE),
        // проверяем только Inf.
        boolean diverged =
                Float.isNaN(m.policyLoss())    || Float.isInfinite(m.policyLoss())
             || Float.isNaN(m.entropy())       || Float.isInfinite(m.entropy())
             || Float.isNaN(m.avgReward())     || Float.isInfinite(m.avgReward())
             || Float.isInfinite(m.valueLoss());   // NaN здесь — норма
        if (diverged) break;

        rewardWindow.addLast(m.avgReward());
        if (rewardWindow.size() > window) rewardWindow.removeFirst();
        float avg = mean(rewardWindow);

        if (avg > bestAvg + minDelta) { bestAvg = avg; stale = 0; }
        else if (++stale >= patience) break;
    }
    return bestAvg;
}
```
