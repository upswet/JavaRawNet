# Глава 13. Policy gradient

## REINFORCE: простейший policy gradient

Политика π(a|s) = softmax(π_net(s)). Агент играет эпизод, собирает траекторию (s_t, a_t, r_t). Returns G_t = Σ_{t'>=t} γ^{t'-t} r_{t'} — «сколько награды получено после шага t».
```text
Loss = −Σ log π(a_t|s_t) · A_t

где A_t = (G_t − baseline) / std.
```
Если действие привело к награде выше среднего — вероятность растёт; ниже — падает.

Baseline — средняя награда по эпизоду. Без baseline REINFORCE нестабилен: все действия поощряются, если награда всегда положительна. Вычитание среднего центрирует advantage вокруг нуля — «хуже среднего» становится отрицательным.

log π(a_t|s_t) — логарифм вероятности, что политика выбрала действие a_t в состоянии s_t. Всегда ≤ 0 (при π = 1 — ноль). Чем реже политика выбирает действие, тем более отрицателен log.

```text
Пример. 
p_left = 0.7,
 p_right = 0.3.

Агент выбрал left: log 0.7 ≈ −0.357.
Агент выбрал right: log 0.3 ≈ −1.204.

Редкое действие (right) имеет больший по модулю log — loss сильнее толкает его, если оно привело к награде.
```

```java
public final class ReinforceTrainer implements RlTrainer {
    @Override
    public void trainIteration() {
        // 1. Собираем траекторию.
        List<Step> trajectory = new ArrayList<>();
        float[] s = env.reset();
        boolean done = false;
        float totalReward = 0f;
        while (!done) {
            float[] logits = policy.forward(s, true);
            int a = Categorical.sample(logits, rnd);
            Environment.StepResult step = env.step(a);
            trajectory.add(new Step(s.clone(), a, step.reward()));  // s.clone() — s может быть буфером среды
            totalReward += step.reward();
            s = step.observation();
            done = step.done();
        }

        // 2. Returns G_t.
        int T = trajectory.size();
        float[] returns = new float[T];
        float G = 0f;
        for (int t = T - 1; t >= 0; t--) {
            G = trajectory.get(t).reward() + gamma * G;
            returns[t] = G;
        }

        // 3. Baseline + нормализация advantage.
        float sumReturns = 0f;
        for (float r : returns) sumReturns += r;
        float baseline = sumReturns / T;

        float[] advantages = new float[T];
        float mean = 0f;
        for (int t = 0; t < T; t++) {
            advantages[t] = returns[t] - baseline;
            mean += advantages[t];
        }
        mean /= T;
        float std = 0f;
        for (int t = 0; t < T; t++) std += (advantages[t] - mean) * (advantages[t] - mean);
        std = (float) Math.sqrt(std / T) + 1e-8f;
        for (int t = 0; t < T; t++) advantages[t] = (advantages[t] - mean) / std;

        // 4. Loss, backward, метрики.
        float policyLossSum = 0f, entropySum = 0f;
        for (int t = 0; t < T; t++) {
            Step step = trajectory.get(t);
            float[] newLogits = policy.forward(step.state(), true);
            float[] p = Categorical.softmax(newLogits);

            float[] dLogits = new float[newLogits.length];
            for (int i = 0; i < dLogits.length; i++) {
                float onehot = (i == step.action()) ? 1f : 0f;
                dLogits[i] = -advantages[t] * (onehot - p[i]);
            }
            // entropy bonus — опционально, см. код ReinforceTrainer.

            policyLossSum -= (float) Math.log(p[step.action()] + 1e-10f) * advantages[t];
            for (float pi : p) entropySum -= pi * (float) Math.log(pi + 1e-10f);

            policy.backward(dLogits);
        }
        policy.update(optimizer, T);

        lastMetrics = RlMetrics.reinforce(totalReward, T, policyLossSum / T, entropySum / T, 1);
    }
}
```

Что происходит на практике

REINFORCE на CartPole сходится частично (~50–110 шагов вместо 500), сильно скачет. 
Это нормально для REINFORCE: высокая дисперсия, не доходит до максимума. 
Но работает — не застревает.

Проблемы:
- Высокая дисперсия. Одна политика даёт разную награду (среда случайна). Градиент шумит.
- Медленно учится. Нужны сотни эпизодов, чтобы заметить прогресс.
- Credit assignment. В длинных эпизодах G_t одинаков для всех ходов (награда только в конце). Модель не знает, какой ход привёл к победе.
- Локальный оптимум. На GridWorld 5×5 с редкой наградой застревает в углу («стоять лучше случайного блуждания»).

## PPO: рабочий стандарт

PPO = Actor-Critic + GAE + clip. Каждый компонент отвечает на конкретную проблему REINFORCE

### Actor-Critic

- Actor — политика π_θ(a|s). Принимает состояние, выдаёт вероятности действий. Учится выбирать действия, приносящие больше награды.
- Critic — функция ценности V_φ(s). Предсказывает, сколько суммарной награды можно получить из данного состояния. Не выбирает действия, а служит «судьёй» для Actor.

Critic нужен, чтобы снизить дисперсию градиента: вместо того чтобы считать долгосрочную отдачу напрямую, мы обучаемся на преимуществе — насколько действие лучше среднего действия в этом состоянии.

Две сети (или одна с двумя головами):

```text
                    ┌─→ Dense(128 → 4)  → logits (actor)
input → Dense(25→128) → LeakyReLU ─┤
                    └─→ Dense(128 → 1)  → V(s) (critic)
                    
Общие слои учатся на двух задачах сразу (policy gradient и MSE). Градиенты от обеих голов идут в общий backbone.                    
                    
input → Dense(25→128) → LeakyReLU → Dense(128→4)  → logits  (actor)
input → Dense(25→128) → LeakyReLU → Dense(128→1)  → V(s)    (critic)           

Свои веса, свои градиенты, свои оптимизаторы. Ничего общего.         
```

Две функции потерь — отдельно для actor и critic. Градиенты идут в разные сети, обновляются разными оптимизаторами.
```text
Actor loss — clipped policy objective
L_actor = −E[ min( r_t(θ) · A_t,  clip(r_t(θ), 1−ε, 1+ε) · A_t ) ]

Critic loss — MSE (или Huber)
L_critic = E[ ( V_φ(s_t) − R_t )² ]
```

### GAE — Generalized Advantage Estimation

Чтобы Actor учился, ему нужно знать не просто «сколько награды я получу», а «насколько моё действие лучше среднего действия в этом состоянии». Эта разница — преимущество (advantage).

Классика: A = R − V(s), где R — фактическая награда, V(s) — предсказание Critic.

Другой вариант — TD-ошибка (temporal difference error):
```text
δ_t = r_t + γ·V(s_{t+1}) − V(s_t)

r_t — награда на шаге t;
γ — дисконт (0 < γ ≤ 1), насколько агент ценит будущие награды;
V(s_t) — текущая оценка ценности («сколько я ожидал получить»);
V(s_{t+1}) — оценка ценности следующего состояния.
```

TD-ошибка — разница между уточнённой оценкой и предыдущим прогнозом:
- δ_t > 0: реальность лучше ожиданий. Ценность V(s_t) стоит повысить.
- δ_t < 0: вышло хуже ожиданий. Ценность V(s_t) стоит понизить.
- δ_t ≈ 0: прогноз был точным.

GAE вводит параметр λ ∈ [0,1], который плавно балансирует между двумя крайностями:
```text
A_t^GAE = Σ_{l≥0} (γλ)^l · δ_{t+l}

λ = 0 — чистая TD-ошибка (A_t = δ_t). Низкая дисперсия, высокое смещение.
λ = 1 — Monte-Carlo (A_t = G_t − V(s_t)). Низкое смещение, высокая дисперсия.
λ ≈ 0.95 — стандарт: компромисс.
```

На всякий случай напомню:
- Дисперсия — насколько разброс результатов вокруг среднего. Высокая дисперсия: каждый запуск даёт сильно разное. Низкая: все запуски близки друг к другу.
- Смещение — насколько среднее результатов отличается от истины. Высокое смещение: даже в среднем мы промахиваемся мимо правильного ответа. Низкое: в среднем попадаем.

```text
Пример: эпизод длины 3, γ = 0.9, V(s) = [0.5, 0.6, 0.7], r = [0.1, 0.2, 0.3].

δ_0 = r_0 + γ·V(s_1) − V(s_0) = 0.1 + 0.9·0.6 − 0.5 = 0.14
δ_1 = r_1 + γ·V(s_2) − V(s_1) = 0.2 + 0.9·0.7 − 0.6 = 0.23
δ_2 = r_2 + γ·V(s_3) − V(s_2) = 0.3 + 0.9·0 − 0.7 = -0.4  (s_3 — конец, V=0)

λ = 0 (TD):
  A_0 = δ_0 = 0.14
  A_1 = δ_1 = 0.23
  A_2 = δ_2 = -0.4
  Дисперсия: низкая (только δ, без суммы).

λ = 1 (MC):
  A_0 = δ_0 + γ·δ_1 + γ²·δ_2 = 0.14 + 0.9·0.23 + 0.81·(-0.4) = 0.14 + 0.207 - 0.324 = 0.023
  A_1 = δ_1 + γ·δ_2 = 0.23 + 0.9·(-0.4) = -0.13
  A_2 = δ_2 = -0.4
  Дисперсия: высокая (сумма δ, каждое δ шумит).

λ = 0.95 (GAE):
  A_0 = δ_0 + γλ·δ_1 + (γλ)²·δ_2 = 0.14 + 0.855·0.23 + 0.731·(-0.4) ≈ 0.14 + 0.197 - 0.292 = 0.045
  A_1 = δ_1 + γλ·δ_2 = 0.23 + 0.855·(-0.4) = -0.112
  A_2 = δ_2 = -0.4
  Компромисс: дисперсия ниже, чем у MC, смещение ниже, чем у TD.
```

### Clip

Клипируем изменение политики, чтобы оно не стало слишком большим. 
Идея: после одного обновления политика не должна сильно отличаться от той, что собирала данные.

```text
ratio = π_new(a|s) / π_old(a|s)
L = −min( ratio · A,  clip(ratio, 1−ε, 1+ε) · A )
```

- Если A > 0 (действие хорошее) и ratio вырос выше 1+ε — min выбирает clip, градиент обнуляется: дальше увеличивать вероятность не нужно.
- Если A < 0 (действие плохое) и ratio упал ниже 1−ε — аналогично.
- Внутри коридора [1−ε, 1+ε] — обычный policy gradient.

Это защита от коллапса политики в локальный оптимум за один шаг.

Почему clip стабилизирует? Policy gradient — это локальная аппроксимация: мы считаем градиент в точке π_old и делаем шаг. Если шаг слишком большой, мы уходим далеко от π_old, и аппроксимация «ломается» — градиент в новой точке может быть совсем другим, и обучение расходится.

Clip ограничивает шаг: ratio не может выйти за [1-ε, 1+ε], то есть новая политика не может сильно отличаться от старой. Это гарантирует, что аппроксимация остаётся локально корректной, и обучение стабильно.

Алгоритм PPO
```text
1. Собрать N траекторий текущей политикой π_θold
2. Для каждого шага t:
     δ_t = r_t + γ·V(s_{t+1}) − V(s_t)
     Â_t = Σ (γλ)^l · δ_{t+l}                       (GAE)
     R̂_t = Â_t + V(s_t)                              (value-таргет)
3. Обновлять политику и критик несколько эпох (обычно 3–10)
   на мини-батчах, минимизируя:
     −E[min(r·Â, clip(r, 1−ε, 1+ε)·Â)]   (клипнутый surrogate loss)
     c1·(V(s) − R̂)²                       (value loss)
     −c2·H(π)                              (энтропийный бонус)
4. π_θold ← π_θ, повторить
```

Rollout (в обучении с подкреплением, особенно в PPO) — процесс, когда агент взаимодействует со средой по текущей политике и собирает данные: последовательность состояний, действий, наград. Результат — одна или несколько траекторий, которые потом используют для обучения.

Код
```java
@Override
public void trainIteration() {
    // 1. Rollout.
    List<Step> rollout = new ArrayList<>(rolloutSteps);
    float[] s = env.reset();
    boolean done = true;
    float totalReward = 0f;
    int episodes = 0;

    for (int t = 0; t < rolloutSteps; t++) {
        if (done) { s = env.reset(); episodes++; }

        float[] logits = actor.forward(s, true);
        int a = Categorical.sample(logits, rnd);
        float value = critic.forward(s, true)[0];

        Environment.StepResult step = env.step(a);
        rollout.add(new Step(s.clone(), a, step.reward(), value, step.done()));
        totalReward += step.reward();
        s = step.observation();
        done = step.done();
    }

    // 2. GAE и returns (обратный проход).
    int n = rollout.size();
    float[] advantages = new float[n];
    float[] returns = new float[n];

    float lastValue = rollout.get(n - 1).done() ? 0f : critic.forward(s, false)[0];
    float gae = 0f;
    for (int t = n - 1; t >= 0; t--) {
        Step st = rollout.get(t);
        float nextValue = st.done() ? 0f : (t == n - 1 ? lastValue : rollout.get(t + 1).value());
        float delta = st.reward() + gamma * nextValue - st.value();
        gae = delta + gamma * gaeLambda * gae;
        advantages[t] = gae;
        returns[t] = gae + st.value();
    }

    // Нормализация advantage (стандарт PPO).
    normalize(advantages);

    // 3. Старые logits для clip.
    float[][] oldLogits = new float[n][];
    for (int t = 0; t < n; t++) {
        oldLogits[t] = actor.forward(rollout.get(t).state(), false).clone();
    }

    // 4. Actor update + метрики (nEpochs раз, мини-батчами).
    updateActor(rollout, oldLogits, advantages, n);

    // 5. Critic update + метрики.
    updateCritic(rollout, returns, n);

    // 6. Метрики итерации.
    lastMetrics = new RlMetrics(
            totalReward,
            episodes > 0 ? (float) n / episodes : 0f,
            policyLoss, valueLoss, entropy, episodes);
}
```

oldLogits восстанавливаются детерминированно (training = false), а не сохраняются из rollout. 
Причина: forward возвращает внутренний буфер сети, и если сохранить ссылку на него, к моменту обновления там уже будут другие числа. 
Поэтому либо .clone() сразу, либо повторный forward с training = false (детерминированный проход без dropout/шума). 
В PPO выбран второй вариант — так oldLogits гарантированно соответствуют политике, которая собирала rollout.

>Почему это важно для clip? Clip считает ratio = π_new / π_old. Если π_old «испортился» (в буфере другие числа), то ratio будет неверным, и clip сработает неправильно. Поэтому π_old должен быть точно тем распределением, которое собирало rollout. Восстановление через training = false гарантирует это.

Clip-градиент. Если clip сработал (ratio вышел за коридор в «невыгодную» сторону), градиент по логитам обнуляется:
```java
float dRatio;
if ((adv > 0 && ratio > 1f + clipEps) || (adv < 0 && ratio < 1f - clipEps)) {
    dRatio = 0f;                  // clip сработал — не двигаем
} else {
    dRatio = -adv * ratio;        // обычный policy gradient
}

float[] dLogits = new float[newLogits.length];
for (int i = 0; i < dLogits.length; i++) {
    float onehot = (i == a) ? 1f : 0f;
    dLogits[i] = dRatio * (onehot - pNew[i]);
}
```

Entropy bonus. Добавляет в градиент компоненту, которая «тянет» политику к равномерному распределению. Без неё политика на GridWorld коллапсирует в первый локальный оптимум за ~10 итераций (энтропия → 0). Формула градиента энтропии по логитам:
```java
if (entropyBonus > 0f) {
    float sumPlogPPlus1 = 0f;
    float[] dEntropy = new float[dLogits.length];
    for (int i = 0; i < dLogits.length; i++) {
        float logP = (float) Math.log(pNew[i] + 1e-10f);
        dEntropy[i] = -pNew[i] * (logP + 1f);
        sumPlogPPlus1 += pNew[i] * (logP + 1f);
    }
    for (int i = 0; i < dLogits.length; i++) {
        dLogits[i] += entropyBonus * (dEntropy[i] - pNew[i] * sumPlogPPlus1);
    }
}
```

Critic update. Отдельный цикл по тем же индексам, MSE между V(s) и returns[t], градиент dV = V(s) − R̂:
```java
for (int epoch = 0; epoch < nEpochs; epoch++) {
    Collections.shuffle(indices, rnd);
    for (int start = 0; start < n; start += miniBatchSize) {
        int end = Math.min(start + miniBatchSize, n);
        int batch = end - start;
        for (int k = start; k < end; k++) {
            int t = indices.get(k);
            float v = critic.forward(rollout.get(t).state(), true)[0];
            float dV = v - returns[t];
            valueLossSum += dV * dV;
            critic.backward(new float[]{ dV });
        }
        critic.update(criticOpt, batch);
    }
}
```

REINFORCE не учится. Это честно: Monte-Carlo returns с редкой наградой (+1 только в одном состоянии из 25) — credit assignment не работает. Градиент от +1 размывается по всей траектории, а −1 за яму доминирует. Политика учится «не падать» (ходит кругами) или «падать быстро» (эпизод короче — меньше шагов до следующего reset).

PPO частично сходится: seed 43/44 нашли цель, seed 42 застрял в «ходить кругами» (epLen=36, H=0.000).

Вывод. Даже PPO может застрять в локальном оптимуме при H=0.000. Это не баг, это свойство RL. Seed 44 нашёл «идти к цели», seed 42 — «ходить кругами». Исследование критично, и entropyBonus — инструмент, который нужно настраивать.

Что исправить, чтобы PPO сходился стабильно:
- PPO_ENTROPY = 0.3 (было 0.1). Главная правка. При H=1.386 (максимум) entropyBonus=0.3 даёт градиент, удерживающий политику от коллапса. Политика исследует дольше, чаще находит цель.
- PPO_CRITIC_LR = 3e-3 (было 1e-3). Critic должен быстро выучить V(s), чтобы GAE был точным. С 1e-3 critic недообучается на первых итерациях, advantage шумный, политика коллапсирует.
- PPO_ROLLOUT = 8192 (было 4096). Больше эпизодов на rollout — стабильнее GAE. При epLen~10 это ~800 эпизодов на rollout. Для GridWorld 25 состояний — более чем достаточно.
