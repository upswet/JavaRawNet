# Задачи для Reinforcement Learning

## CartPole — тележка с шестом

Классическая среда из библиотеки Gym (OpenAI).
Тележка движется по горизонтальной прямой, на ней закреплён шест.
Агент может толкать тележку влево или вправо.
Задача — не дать шесту упасть как можно дольше.

### Постановка

- **Наблюдение** (`observationSize = 4`): `[x, x', θ, θ']` — позиция тележки, её скорость, угол шеста, угловая скорость.
- **Действия** (`numActions = 2`): `0` — толкнуть влево, `1` — толкнуть вправо.
- **Награда**: `+1` за каждый шаг, пока шест не упал.
- **Конец эпизода**: `|θ| > 12°` или `|x| > 2.4`, или достигнут лимит `500` шагов.

### Почему CartPole хорош для policy gradient

- Награда **частая** (`+1` каждый шаг) — credit assignment простой.
- Локального оптимума **нет** — «стоять нельзя», шест упадёт.
- REINFORCE, Actor-Critic и PPO **все** сходятся, разница — скорость и стабильность.

- [CartPole.java](cart_pole/CartPole.java) — среда.
- [CartPoleAlgorithmsComparison.java](cart_pole/CartPoleAlgorithmsComparison.java) — сравнение REINFORCE и PPO (3 seed).
- [CartPoleValueBasedComparison.java](cart_pole/CartPoleValueBasedComparison.java) — сравнение Q-learning (tabular), DQN и Double DQN.


## GridWorld 5×5 — сетка с ловушками

Классическая среда из книги Sutton & Barto.
Агент ходит по сетке 5×5, ищет цель, обходит ямы.

### Постановка

- **Наблюдение** (`observationSize = 25`): one-hot позиции агента (25 чисел, `1` на позиции агента, `0` остальные).
- **Действия** (`numActions = 4`): `0` — вверх, `1` — вниз, `2` — влево, `3` — вправо.
- **Награда**:
    - обычный шаг: `0`;
    - яма: `−1`, эпизод закончен;
    - цель: `+1`, эпизод закончен;
    - лимит шагов (`50`): `0`, эпизод обрывается.
- **Старт**: случайная клетка (не яма, не цель).

### Почему без штрафа за шаг

Штраф за шаг (`−0.01`) + штраф за яму (`−1`) создают **локальный оптимум**: «не падать в яму любой ценой» выгоднее, чем «дойти до цели».
Агент ходит кругами 50 шагов (`−0.5`) вместо падения (`−1`) — формально оптимально локально, но глобальный оптимум (`+1`) недостижим.
Классическая схема (`0` за шаг) убирает этот локальный оптимум.

- [GridWorldAlgorithmsComparison.java](grid_word/GridWorldAlgorithmsComparison.java) — сравнение REINFORCE и PPO (3 seed).
- [GridWorldValueBasedComparison.java](grid_word/GridWorldValueBasedComparison.java) — сравнение Q-learning (tabular), DQN и Double DQN.


## Сравнение алгоритмов

### Policy-based vs Value-based

| Критерий | Policy gradient (REINFORCE, PPO) | Value-based (DQN, Double DQN) |
|---|---|---|
| Объект | `π(a|s; θ)` — распределение | `Q(s,a; θ)` — ценность |
| Что хотим | максимизировать `E[G]` | минимизировать `(Q − target)²` |
| Выход | вероятности | числа |
| Loss | `−G·log π(a|s)` | `Huber(Q(s,a) − target)` |
| Политика | сама `π` | `argmax Q` (выводится) |
| Исследование | сэмплирование + entropy | ε-greedy (внешнее) |
| Непрерывные действия | Да | Нет (нужен перебор) |
| Стабильность | Низкая (высокая дисперсия) | Высокая (TD-ошибка) |

### Когда какой алгоритм

| Задача | Алгоритм | Почему |
|---|---|---|
| Маленькая дискретная среда (GridWorld, TicTacToe) | Q-learning (tabular) | Проще всех, сходится за сотни эпизодов |
| Большая дискретная среда (Atari, карточные игры) | DQN | Нейросеть + replay, эффективно по данным |
| Непрерывные действия (робот, управление) | PPO / SAC | `argmax` невозможен, нужно распределение |
| Мало данных, дорогой сбор | PPO | On-policy, но стабилен, работает «из коробки» |
| Много данных, дешёвый сбор | DQN / SAC | Off-policy, эффективнее по данным |
| Нужна детерминированная политика | DQN | `argmax` — детерминизм |
| Нужно исследование | PPO | Entropy bonus — встроенное |
