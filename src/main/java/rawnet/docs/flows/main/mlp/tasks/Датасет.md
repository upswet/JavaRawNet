# Источник данных (датасет)

Датасет — это набор примеров, на которых сеть учится и проверяется. 
Один пример — это пара (вход, целевой выход). 
Всё остальное (батчи, перемешивание, ленивая загрузка) — это обёртки над списком примеров, которые решают конкретные практические проблемы.

В зависимости от задачи и объёма данных датасет может принимать три формы:
- Список примеров — самый простой случай: все данные в памяти, есть train и test.
- Пример с N входами — для архитектур, где на вход подаётся не один вектор, а несколько (multi-modal, multi-query).
- Ленивый стрим — когда данных так много, что они не помещаются в память, и их нужно генерировать/подгружать по требованию.


## Отдельный пример (один вход, один выход)

Базовый строительный блок — один обучающий пример. У него есть входной вектор (то, что подаём сети) и целевой вектор (то, что сеть должна выдать). Больше ничего не нужно: батч, перемешивание и загрузка — это задачи датасета, а не примера.

```java
/**
 * Единичный обучающй пример для MLP и CNN нейросетей
 */
@RequiredArgsConstructor
@Getter
public class Sample {
    /**Входной вектор*/
    private final float[] inputs;
    /**Выходной вектор*/
    private final float[] targets;
}
```

Почему float[], а не double[]? В нейросетях float (32 бита) — стандарт: точности хватает, а память и скорость в 2 раза лучше, чем у double. double используют только в научных расчётах, где важна каждая цифра.

Почему final? Пример — иммутабельный. После создания его нельзя изменить. Это защищает от случайной порчи данных (например, если один слой «забудет» восстановить вход после модификации) и позволяет безопасно передавать пример между потоками.


## Отдельный пример для N-входов (на один выход)

Иногда на вход сети подаётся не один вектор, а несколько. Классические примеры:
- Multi-modal: текст + изображение + аудио (каждый модальность — свой вектор).
- Multi-query: Q-вектор + N−1 групп key-value (используется в некоторых архитектурах внимания).
- Encoder-decoder: вход кодера + состояние декодера.

Для этого нужен пример, который хранит массив входов, а не один вектор.

```java
/**
 * Один пример с <b>N входами</b> ({@code N >= 1}) и целевым вектором.
 *
 * <p>Обобщение {@link Sample} на произвольное число входов.
 * Нужен для multi-query / multi-modal архитектур, где входов больше
 * двух: Q + N−1 KV-групп, text + image + audio и т.п.*/
public final class NInputSample {
    private final float[][] inputs;
    private final float[] targets;

    /**
     * @param inputs  входы в порядке {@code forwardN}; {@code length >= 1},
     *                каждый элемент не {@code null}
     * @param targets целевой вектор; не {@code null}
     */
    public NInputSample(float[][] inputs, float[] targets) {
        Objects.requireNonNull(inputs, "inputs");
        if (inputs.length < 1)
            throw new IllegalArgumentException("NInputSample: inputs.length >= 1, получено " + inputs.length);
        for (int i = 0; i < inputs.length; i++)
            Objects.requireNonNull(inputs[i], "inputs[" + i + "]");
        this.inputs = inputs;
        this.targets = Objects.requireNonNull(targets, "targets");
    }

    public float[][] getInputs() {
        return inputs;
    }

    public float[] getTargets() {
        return targets;
    }

    /**
     * @return число входов в примере (совпадает с длиной {@code inputs})
     */
    public int nInputs() {
        return inputs.length;
    }
}
```

Почему inputs — это float[][], а не List<float[]>? Массив быстрее (нет боксинга, лучше кэш-локальность) и проще сериализуется. List был бы уместен, если бы число входов менялось динамически, но в NInputSample оно фиксировано на момент создания.

## Датасет

Датасет — это контейнер для train и test выборок. Он параметризован типом примера T: это может быть Sample, NInputSample или любой другой класс. Такой подход называется generic и позволяет иметь один класс датасета на все типы примеров, а не дублировать его для каждого.

```java
/**
 * Датасет: train и test — списки примеров одного типа {@code T}.
 *
 * <p>Тип {@code T} — это тип примера: {@link Sample} для
 * одного входа, {@link NInputSample} для N входов,
 * любой другой — для будущих архитектур.
 *
 * <p><b>Зачем generic.</b> Один контейнер на все типы примеров:
 * {@code Dataset<SampleSimple>} и {@code Dataset<NInputSample>} —
 * это <b>один</b> класс с разными параметрами, а не два разных
 * класса. Меньше дублирования, легче добавлять новые типы.
 *
 * <p><b>Инвариант.</b> {@code trainSamples} и {@code testSamples}
 * должны содержать примеры <b>одного</b> типа. Проверка не делается
 * в конструкторе (дженерики стираются), но компилятор гарантирует
 * это на уровне типов.
 *
 * @param <T> тип примера
 */
@Getter
public final class SampleDataset<T> {

    private final List<T> trainSamples;
    private final List<T> testSamples;

    public SampleDataset(List<T> trainSamples, List<T> testSamples) {
        this.trainSamples = Objects.requireNonNull(trainSamples, "trainSamples");
        this.testSamples  = Objects.requireNonNull(testSamples,  "testSamples");
    }

    /**
     * Разбить общий пул примеров на train/test.
     *
     * <p>Перемешивает {@code allSamples} <b>на месте</b>, затем режет
     * по {@code procent}. Возвращает <b>новый</b> {@code Dataset<T>};
     * исходный список не сохраняется в датасете (копируются подсписки).
     *
     * @param allSamples общий пул; перемешивается
     * @param procent    доля train в {@code (0, 1)}; например, {@code 0.8f}
     * @param <T>        тип примера
     * @return {@code Dataset<T>} с train (первые {@code procent})
     *         и test (остальные)
     * @throws IllegalArgumentException если {@code procent} вне {@code (0, 1)}
     */
    public static <T> SampleDataset<T> split(List<T> allSamples, float procent) {
        if (procent <= 0f || procent >= 1f)
            throw new IllegalArgumentException("procent in (0, 1), получено " + procent);
        Collections.shuffle(allSamples);
        int trainSize = (int) (allSamples.size() * procent);
        return new SampleDataset<>(
                new ArrayList<>(allSamples.subList(0, trainSize)),
                new ArrayList<>(allSamples.subList(trainSize, allSamples.size()))
        );
    }
}
```

Проблема. Если датасет — это миллионы изображений по 1 МБ, он занимает терабайты. В оперативную память он не поместится. Нужен способ генерировать примеры по требованию: прочитали батч с диска → обучились → выбросили → прочитали следующий.

## Ленивый стрим

Проблема. Если датасет — это миллионы изображений по 1 МБ, он занимает терабайты. В оперативную память он не поместится. Нужен способ генерировать примеры по требованию: прочитали батч с диска → обучились → выбросили → прочитали следующий.

Для этого используется ленивый источник — "SampleStream". Это не список, а фабрика итераторов: каждый вызов open() возвращает новый итератор, который генерирует примеры «на лету».

```java
/**
 * Ленивый источник примеров: не хранит всё в памяти, генерирует по
 * требованию.
 *
 * <p><b>Generic {@code <S>}</b> — чтобы работать и с
 * {@link Sample}, и с {@link NInputSample}, и с
 * любым другим типом примера.
 *
 * @param <S> тип примера
 */
public interface SampleStream<S> extends Closeable {

    Iterator<S> open();

    default int size() { return -1; }

    /**
     * Тестовая выборка для метрик.
     *
     * <p><b>Обязателен к реализации.</b> {@code SampleStream} — ленивый
     * источник train; тестовая выборка обычно небольшая и
     * материализованная. Пользователь сам решает, откуда её взять:
     * <ul>
     *   <li>отдельный файл/БД/список — загрузить в {@code getTestSamples()};</li>
     *   <li>нет тестовой выборки — вернуть {@link List#of()} (метрики
     *       на test не считаются);</li>
     *   <li>тест = часть train — вернуть подвыборку (но осторожно:
     *       это уже не «test»).</li>
     * </ul>
     *
     * <p><b>Почему не default.</b> Если бы был {@code default List.of()},
     * пользователь мог бы **забыть** реализовать и не заметить, что
     * метрики на test не считаются. Обязательный метод — компилятор
     * напомнит.
     *
     * @return тестовая выборка; не {@code null} (может быть пустой)
     */
    List<S> getTestSamples();

    @Override default void close() throws IOException {}

    // ---- фабрики ----

    static <S> SampleStream<S> of(List<S> samples, List<S> testSamples) {
        if (samples == null) throw new IllegalArgumentException("samples == null");
        return new SampleStream<>() {
            @Override public Iterator<S> open() { return samples.iterator(); }
            @Override public int size() { return samples.size(); }
            @Override public List<S> getTestSamples() { return testSamples; }
        };
    }

    static <S> SampleStream<S> fromIterator(Factory<S> factory, int size, List<S> testSamples) {
        if (factory == null) throw new IllegalArgumentException("factory == null");
        return new SampleStream<>() {
            @Override public Iterator<S> open() { return factory.create(); }
            @Override public int size() { return size; }
            @Override public List<S> getTestSamples() { return testSamples; }
        };
    }

    static <S> SampleStream<S> fromSupplier(Supplier<S> next, int size, List<S> testSamples) {
        if (next == null) throw new IllegalArgumentException("next == null");
        return new SampleStream<>() {
            @Override
            public Iterator<S> open() {
                return new Iterator<>() {
                    private S buf;
                    private boolean done;
                    @Override public boolean hasNext() {
                        if (done) return false;
                        if (buf == null) {
                            buf = next.get();
                            if (buf == null) done = true;
                        }
                        return buf != null;
                    }
                    @Override public S next() {
                        if (!hasNext()) throw new NoSuchElementException();
                        S r = buf; buf = null; return r;
                    }
                };
            }
            @Override public int size() { return size; }
            @Override public List<S> getTestSamples() { return testSamples; }
        };
    }

    default Stream<S> stream() {
        return StreamSupport.stream(
                Spliterators.spliteratorUnknownSize(open(), Spliterator.ORDERED), false);
    }

    @FunctionalInterface
    interface Factory<S> {
        Iterator<S> create();
    }
}
```

Почему open(), а не iterator()? Потому что SampleStream можно переоткрывать. Один и тот же стрим можно использовать для нескольких эпох: каждая эпоха вызывает open() и получает свежий итератор. Если бы метод назывался iterator() и возвращал тот же итератор, вторая эпоха получила бы пустой итератор (он уже исчерпан).

Почему size() возвращает -1, а не бросает исключение? -1 — это соглашение «размер неизвестен». Для ленивых стримов (например, читающих из БД) размер может быть неизвестен заранее. -1 позволяет вызывающему коду проверить size() >= 0 и решить, можно ли использовать размер (например, для прогресс-бара).

Почему getTestSamples() обязателен? Это осознанное решение. Если бы у метода была реализация по умолчанию (return List.of()), пользователь мог бы забыть реализовать его, и метрики на test молча не считались бы. Обязательный метод — компилятор напомнит, что тестовая выборка нужна.

Почему fromSupplier такой сложный? Потому что Supplier<S> не умеет сигнализировать «данные кончились». Если Supplier.get() возвращает null, это может означать и «конец данных», и «ошибка». Мы договорились: null от Supplier = конец данных. Итератор кэширует последний элемент в buf, чтобы hasNext() не вызывал get() дважды (это важно, если get() имеет побочные эффекты — например, читает с диска).

Почему stream() — default? Потому что это удобная обёртка над open(). Она не требует дополнительного состояния, и её реализация одинакова для всех стримов. default-метод позволяет не дублировать код в каждом анонимном классе.
