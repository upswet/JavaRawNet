Три задачи покрывают три ключевых сценария MLP:

- Аппроксимация функции — регрессия: выход — непрерывное число. Минимальный датасет, быстрый цикл, видно, как сеть «подстраивается» под формулу.

## Задача апроксимации функции

Мы загадываем формулу функции от нескольких переменных и с некоторой случайной погрешностью вычисляем её значения.
По полученному датасету (набору данных) наша самописная нейронка должна будет отгадать значение функции для тех значений переменных которых не было в обучающем наборе данных.

Это классическая задача регрессии - предсказание непрерывного числа. Например значения функции или цены дома.
Ну или значения функции нескольких переменных.

Наш набор данных(датасет) будем генерировать мы сами, и он представляет собой два вектора данных:\
Вектор входных данных: Переменная 1, переменная 2… переменная Н\
Вектор выходных данных: значение функции.

```java
/**Задача апроксимации функции*/
public class FunctionApproximation {
    /**Сгенерировать набор данных для задачи апроксимакции функции
     * @param fun - сама функция
     * @param sampleCount - количество генерируемых примеров
     * @param xCount - кол-во входных аргументов функции
     * @param inputRange - промежуток в котором будут меняться элементы входного вектора для фун
     * @return - список примеров*/
    public static List<SampleSimple> generateDatasetForTaskFunctionApproximation(Function<float[], float[]> fun, int xCount, int sampleCount, float inputRange){
        List<SampleSimple> result = new ArrayList<>(sampleCount);
        for(int i=0; i<sampleCount; i++){
            float[] input = new float[xCount];
            for(int j=0; j<xCount; j++)
                input[j] = (float) (Math.random() * inputRange - inputRange / 2);
            float[] target = fun.apply(input);
            result.add(new SampleSimple(input, target));
        }
        return result;
    }
}
```

### Задача классификации ирисов

Также задача классификации.

Это классическая задача классификации в машинном обучении, основанная на данных о цветках трёх видов ириса.
Она считается «Hello, world!» для алгоритмов классификации и часто используется для демонстрации работы моделей.

Подробнее см: https://habr.com/ru/companies/ruvds/articles/679988/?ysclid=mvd5ffsq6678848698

Описание набора данных

Признаки (4 числовых):
+ длина чашелистика (sepal length), см
+ ширина чашелистика (sepal width), см
+ длина лепестка (petal length), см
+ ширина лепестка (petal width), см

Целевая переменная (класс): вид ириса — один из трёх:
+ Iris setosa (щетинистый)
+ Iris versicolor (разноцветный)
+ Iris virginica (виргинский)

Объём: 150 экземпляров, по 50 на каждый класс. Выборка сбалансирована.

Суть задачи: по четырём измерениям цветка необходимо предсказать, к какому из трёх видов он принадлежит. Это задача многоклассовой классификации.

```java
/**Задача классификации ирисов*/
public class Iris {
    /**
     * Преобразовать набор данных "Ирисы" в используемый формат
     * @param path - путь к файлу с датасетом для задачи классификации ирисов
     * @return - вернёт готовый датасет
     */
    @SneakyThrows
    public static List<SampleSimple> prepareDataForIris(Path path) {
        List<SampleSimple> result = new ArrayList<>();

        List<String> list = Files.readAllLines(path);
        for (String s : list) {
            if (s.isBlank()) continue;

            String[] sarr = s.split(",");

            float[] target = new float[3];
            Arrays.fill(target, 0);
            switch (sarr[sarr.length-1]){
                case "Iris-setosa" -> target[0] = 1;
                case "Iris-versicolor" -> target[1] = 1;
                case "Iris-virginica" -> target[2] = 1;
            }

            float[] input = new float[sarr.length - 1];
            for (int j = 0; j < sarr.length-1; j++)
                input[j] = (Float.valueOf(sarr[j]) / 10); // Потому что признаки в см (4.0–7.9), и деление на 10 даёт 0.4–0.79 — «примерно в [0,1]»

            result.add(new SampleSimple(input, target));
        }
        return result;
    }
}
```

Задача классификации ирисов — это многоклассовая классификация (1 из N): каждый цветок принадлежит ровно одному из трёх видов. 
Для такого случая стандарт — Softmax на выходном слое + CrossEntropy.

Если бы задача была multi-label (цветок может быть одновременно, например, «setosa» и «versicolor» — что биологически невозможно, но как пример), то Softmax не подходит, потому что он нормирует сумму вероятностей в 1. В этом случае использовали бы независимые Sigmoid на каждый выход + BinaryCrossEntropy. Но для ирисов это не так.

### Задача MNIST

Это задача классификации, то есть отнесение объекта к одной из нескольких категорий.
Также задачей классификации считается задача отнесения объекта к одной из двух категорий (например "это кошка или это не кошка").

Набор данных MNIST (Modified National Institute of Standards and Technology) содержит изображения цифр от 0 до 9, написанных от руки, и цель — по картинке определить, какая цифра изображена.

Описание набора данных \
Признаки: каждое изображение — квадрат 28×28 пикселей в градациях серого.
Итого 784 входных признака (значения яркости пикселя от 0 до 255, обычно нормализуются в диапазон [0,1]).

Целевая переменная: цифра от 0 до 9 (10 классов).\
Объём:
+ 60 000 изображений для обучения (training set).
+ 10 000 изображений для тестирования (test set).
+ Классы почти сбалансированы (каждой цифры примерно по 6000 в обучении и 1000 в тесте).

Суть задачи: По входному изображению 28×28 модель должна выдать одну из десяти меток — цифру

Подробнее см: https://blog.skillfactory.ru/glossary/mnist-dataset/?ysclid=mvd4ztq32686754370

Вообще-то задача распознавания изоображений требует CNN-нейросетей чтобы отследить повторяющуюиеся детали, но, в простом случае, возможно использование MLP-нейросети.
Тем более для мелких изображений одинакового размера.

Mnist - это уже готовый датасет, но его требуется предварительно обработать, в частности перевести цвет пикселей в диапазон от 0 до 1 с сохранением пропорций относительно других пикселей.

```java
/**Задача распознавания рукописных цифр - mnist*/
public class Mnist {
    /**
     * Преобразовать набор данных MNIST в используемый формат
     * @param path - путь к файлу с датасетом для задачи
     * @return - вернёт готовый датасет
     */
    @SneakyThrows
    public static List<SampleSimple> prepareDataForMnist(Path path) {
        List<SampleSimple> result = new ArrayList<>();

        List<String> list = Files.readAllLines(path);
        for (String s : list) {
            String[] sarr = s.split(",");

            float[] target = new float[10];
            Arrays.fill(target, 0);
            target[Integer.valueOf(sarr[0])] = 1;

            float[] data = new float[sarr.length - 1];
            for (int j = 1; j < sarr.length; j++)
                data[j - 1] = (float) ((Double.valueOf(sarr[j]) / 255.0));

            result.add(new SampleSimple(data, target));
        }
        return result;
    }
}
```

Но и одна эпоха для cnn длится дольше так как гораздо больше вычислений.

MLP_fun — это residual-архитектура (с AddSpec), которая должна учиться лучше, чем MLP_seq, но (из-за простоты задачи), в нашем случае проигрывает mlp_seq
```text
x → dense(784→256) → h
h → LeakyReLU → dense(256→256) → h2
r = h + h2        // <-- остаточная связь
r → dense(256→10)
```

Residual (остаточная связь) — это приём, который позволяет обучать очень глубокие сети, не теряя градиент.

Обычный слой учится функции H(x).

Residual-блок учится разности (остатку) F(x) = H(x) - x

А выход блока считается как y=F(x)+x

То есть мы прибавляем вход к выходу.
Сеть не обязана «с нуля» выучивать полезное преобразование — ей достаточно выучить поправку к исходному x.

Градиент при обратном распространении идёт через + напрямую (производная от x равна 1). Он не проходит через веса слоёв и активации, поэтому не затухает. В глубоких сетях (50, 100+ слоёв) без residual градиент просто «умирает» по пути назад, и первые слои не учатся. Residual даёт градиенту «шоссе» в обход.

На мелких сетях (1–3 слоя) residual часто не даёт выигрыша, а иногда и проигрывает простому MLP — глубины, на которой он «включается», ещё нет. Именно это вы и увидели на MNIST: MLP_fun (1 residual-блок) не обогнал MLP_seq (2 обычных слоя).
